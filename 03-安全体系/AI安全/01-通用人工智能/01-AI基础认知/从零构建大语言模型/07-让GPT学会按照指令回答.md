# 让 GPT 学会按照指令回答

第六章让 GPT 返回固定类别，这一章保留文字生成输出层，从预训练 GPT-2 出发，用指令与参考回答继续训练，让续写更贴近用户要求。

## 从“会续写”到“会回答”，差在哪里

预训练 GPT 的基本动作始终是预测下一个 token。看到一段话后，它可以接着写，但<strong>能续写，不等于一定按要求办事</strong>。本章从保留文字生成能力的预训练模型开始，不使用第六章换过分类输出层的模型。

例如给它一句话：

> Rewrite the sentence using a simile. The car is very fast.

我们希望它把句子改成比喻句，例如：

> The car is as fast as lightning.

如果模型只是继续写有关汽车的文章，没有完成“改成比喻句”的要求，那它会续写，却没有很好地遵循指令。

第七章用“要求及其参考回答”的样本，继续训练预训练模型。这叫<strong>监督式指令微调</strong>，常简称 SFT，其中“监督”指样本明确给出参考回答。目标不是让模型放弃下一 token 预测，而是让它在看到指令时，更可能续写出符合要求的回答。

## 与第六章的短信分类有什么不同

第六章的任务是从固定类别里选一个结果：

```text
短信 → 正常 / 垃圾
```

第七章仍让模型生成文字，因此同一个模型可以面对不同形式的指令：

```text
改写句子 → 生成改写后的句子
回答问题 → 生成文字答案
翻译内容 → 生成译文
```

| | 第六章：分类微调 | 第七章：指令微调 |
| --- | --- | --- |
| 输出 | 预先规定的类别 | 一个接一个生成的 token |
| 输出层 | 换成类别输出层 | 保留面向词表的生成输出层 |
| 本书更新的参数 | 新分类层、最后一个 Transformer 块和最终 LayerNorm | 整个预训练模型 |
| 使用场景 | 固定的短信分类任务 | 训练数据覆盖的多种指令任务 |

这种生成方式更灵活，却不保证模型对任意新任务都能正确回答。它的能力仍受预训练、微调数据和模型本身的限制。

## 参考回答从哪里来

预训练时，原始文章自身就提供了下一个 token 的目标；做指令微调时，仅有“请改写这句话”并不能自动告诉程序什么回答合适，所以需要准备带参考回答的数据。

仓库的[指令数据](https://github.com/rasbt/LLMs-from-scratch/blob/f49cad747931fe6af0a7d2802cd480d1c1a0ec8e/ch07/01_main-chapter-code/instruction-data.json)中，每条样本包含：

| 字段 | 含义 | 例子 |
| --- | --- | --- |
| `instruction` | 要模型做什么 | Rewrite the sentence using a simile. |
| `input` | 完成任务所需的材料，可为空 | The car is very fast. |
| `output` | 供训练使用的参考回答 | The car is as fast as lightning. |

这些参考回答来自教材作者为本章准备的数据集。对于改写、解释等开放任务，一条指令可以有多个合理回答；数据集提供其中一种，供训练时比较。

这里的 `input` 是<strong>样本里的补充材料</strong>，不是说 `instruction` 不属于模型输入。训练时，指令和补充材料都会送给模型。

## 为什么要把样本整理成统一格式

程序要让模型看清要求、材料与回答边界。完整模板如下，来自配套实现的 Alpaca 风格格式；英文说明与各字段按原有顺序排列。

> Below is an instruction that describes a task.  
> Write a response that appropriately completes the request.  
>
> `### Instruction:`  
> Rewrite the sentence using a simile.  
>
> `### Input:`  
> The car is very fast.  
>
> `### Response:`  
> The car is as fast as lightning.  

如果 `input` 为空，就不加入 `### Input:` 部分。`### Instruction:`、`### Input:`、`### Response:` 是<strong>本章使用的数据格式标记</strong>，由程序拼接；模型通过训练学习它们与后续内容的关系。

训练数据包含整段文字和参考回答，为什么模型不会直接抄答案？先用简化的问答格式，把一个样本拆成两步看（暂时把“红色”和“。”各当作一个 token）：

```text
训练（原文答案是“红色。”）：
已知“问题：杯子是什么颜色？回答：”
→ 预测“红色”，与原文比较

已知“问题：杯子是什么颜色？回答：红色”
→ 预测“。”，与原文比较

使用（假设先生成“红色”）：
输入“问题：杯子是什么颜色？回答：”
→ 生成“红色”

再输入“问题：杯子是什么颜色？回答：红色”
→ 继续生成下一项
```

训练的第二步可以用原文中的“红色”当作<strong>已知前文</strong>，但第一步预测“红色”时不能提前看到它。因果遮罩限制每个位置只能参考自己和此前的内容；实际训练会同时计算多个位置，不必真的像上面那样逐行调用模型。使用时没有参考回答，后一步只能接着模型刚生成的内容继续写。如果第一步生成了别的词，后面的输入也会随之改变。本例省略了本章使用的 `###` 标记；实际生成时由程序怎样准备输入，在[“训练好后，用户怎样提问”](#训练好后用户怎样提问)中说明。

## 一个 batch 里长短不同的样本怎么处理

不同指令和回答长度不同。为了把多条样本放进同一个 batch，程序先找到这一批中最长的样本，再给较短的样本补齐长度。

本章使用 GPT-2 的 `<|endoftext|>` token（ID 为 `50256`）兼作结束标记和填充标记。可把它想成：一条回答写完后先放一个“到此结束”，为了凑齐 batch 长度，后面还可能再放几个相同标记。

```text
样本 A：指令 → 回答 → 结束
样本 B：指令 → 回答 → 结束
再补：填充 → 填充
```

![指令、材料、回答和第一个结束标记计入损失，后续额外填充被忽略](./图示/指令损失.svg "每格代表一段 token；主线代码只排除多余填充，并未排除指令部分。")

训练目标仍是错开一位的“下一个 token”。本章会保留回答后<strong>第一个</strong>结束标记作为训练目标，让模型有机会学到回答何时结束；后面仅为补长度而加入的同类标记，则从损失计算中排除。否则模型会花力气学习反复预测没有实际内容的填充。

还有一个容易弄混的细节：<strong>本章没有把指令部分从损失中排除</strong>。指令、补充材料和回答中的有效 token 都参与下一 token 预测；被排除的是多余填充。只对回答部分计算损失也是一种可能的设计，但不是这里主线代码采用的做法。

## 微调时，模型究竟学了什么

程序重新加载第五章介绍过的 GPT-2 预训练权重，再进行指令微调；它既不是从随机参数开始，也不是沿用第六章已经改成分类器的权重。

```text
一批格式化样本
→ 分词器转换成 token ID
→ 模型预测各位置的下一个 token
→ 与样本中的目标 token 比较，计算损失
→ 反向传播求梯度
→ 优化器调整模型参数
```

这和第五章的训练机制相同，区别主要在<strong>练习材料</strong>：第五章主要用普通文本练习续写，第七章用“指令、可选输入、参考回答”组成的文本练习。仓库本章把整个模型的参数交给优化器更新，包含保留下来的生成输出层；这与第六章只更新一部分参数的做法不同。

因此，所谓“学会翻译或改写”，不是程序看到“翻译”两个字就执行一条预先写好的分支规则。训练改变了模型内部的许多数字，使它在这类上下文后更倾向于生成合适的后续 token。

## 为什么还要分训练集、验证集、测试集

模型可能记住练过的回答，却不会处理没见过的指令。为区分这两件事，本章把数据分开使用：

| 数据 | 用途 | 会据此更新模型吗 |
| --- | --- | --- |
| 训练集 | 提供指令和参考回答，计算训练损失 | 会 |
| 验证集 | 训练期间观察未参与更新的样本损失 | 不会 |
| 测试集 | 训练结束后生成回答并检查质量 | 不会 |

主线代码大约使用 85% 作训练集、5% 作验证集、10% 作测试集。比例是本章的设置，不是所有项目都必须采用的标准。

例如模型在训练时总见到“红色杯子是什么颜色？→ 红色”，如果碰到“蓝色杯子是什么颜色？”仍回答“红色”，它可能记住了答案，却没学会从当前材料中找颜色。训练损失下降只能说明它越来越适应练过的数据；验证集和测试集帮助我们观察它面对新数据时怎样表现。

## 训练好后，用户怎样提问

用户可以直接在应用中提出要求，程序负责整理成前面展示的格式。这里要对齐配套代码的实际做法：生成输入包含英文说明、`### Instruction:` 和可选的 `### Input:`，但不预先加上 `### Response:`。

继续看汽车样本，省略相同的英文说明后，两种输入的边界如下：

训练时，正文包含 `### Response:` 和参考回答，随后程序添加结束标记并按 batch 补齐、制作右移目标。生成时，提示停在 `The car is very fast.` 末尾，后面的回答标记和正文需要模型续写。

一次可能的生成结果是：

```text
### Response:
The car is as fast as lightning.
```

`### Response:` 和回答都不在生成输入中。模型可能先写出标记再写正文，程序会去掉展示结果中的回答标记；这不保证每次都会成功遵循格式。生成过程中也不提供 `output` 字段中的参考回答。

运行流程是：用户提出要求 → 程序整理指令与材料 → 模型逐步生成 → 程序提取并展示回答。遇到结束 token 或达到最大新增 token 数时停止。实际聊天产品可以采用其他消息格式，关键是使用时的输入方式应与模型适应的训练格式匹配。

## 损失变小，是否就代表回答好了

损失衡量模型对数据中<strong>特定参考文本</strong>的预测。它适合训练，却不能单独说明回答是否准确、有用。

例如本章测试样本要求把 “The car is very fast.” 写成比喻句：

```text
参考回答：
The car is as fast as lightning.

模型回答：
The car is as fast as a bullet.
```

两者用词不同，但模型回答也符合“使用比喻”的要求。反过来，一个回答即使出现了参考答案的部分词语，也可能事实错误或没有完成任务。因此，开放式回答不能像第六章的固定类别分类那样，只靠“与唯一标签是否相同”统计准确率。

本章先直观看测试集的“指令、参考回答、模型回答”，再演示使用另一个较大的语言模型辅助评分。另一个测试样本问与雷暴相关的云，模型回答了较接近却不够准确的云名：这提醒我们，<strong>回答像那么回事，不等于事实正确</strong>。评委模型可以结合任务要求评估回答，但它给出的分数也可能受评判标准和自身错误影响，不能当作绝对真值。

## 保存成果，以及这章没有解决什么

微调结束后，仓库保存调整过的模型权重，也保存测试集上生成的回答，方便之后查看和评估。以后要运行这个模型，仍需匹配的<strong>模型结构与配置、权重、分词器，以及生成程序</strong>。权重是一堆数字，不会脱离执行这些计算的程序独自运行。

还要区分<strong>当前对话的上下文</strong>与<strong>训练成果</strong>：如果用户先说“桌上有个红色杯子”，再问“它是什么颜色？”，程序需要把前一句也交给模型，模型才有机会利用它。把历史消息放进本次上下文，不等于重新训练或永久修改权重。本章数据主要是一条指令对应一条回答，并没有专门完整训练多轮聊天产品所需的全部行为。

## 七章之后，可以继续做什么

读到这里，应当能沿着一条完整路径解释 GPT：文字变成 ID 与向量，注意力结合上下文，多个 Transformer 块加工表示，输出层给候选 token 打分；训练用损失更新参数，生成按选择策略逐步接出文字。分类微调替换输出目标，指令微调则保留生成方式、改变训练材料。
