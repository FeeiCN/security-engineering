# 风险防御对抗

接口上线、员工访问内部系统、Agent 调用业务工具，都需要明确谁能访问、能执行什么、数据能流向哪里，以及异常发生后怎样停止和恢复。本章按这些建设问题串联现有防御实践，读者可以从当前需要保护的访问或操作开始。

## 身份与权限

保护员工账号时，从[密码安全实践](/password-security)了解密码管理与多因素认证；需要把身份、设备和内部访问连接起来时，参考[员工侧安全一站式解决方案](/gugu)，该文保留历史演讲方案。

当操作由 Agent 发起时，[Agent 与工具调用安全](/ai-agent-tool-security)解释模型提议如何经过授权再执行；[Agent 权限撤销与异步执行](/agent-authorization-revocation)进一步检查撤销后尚未结束的任务与业务副作用。

## 应用与接口

应用间调用可以从 [API 安全](/api-security)的传输保护、调用方识别和请求签名讨论开始；涉及资源 ID 的接口，结合[加密资源 ID 缓解水平越权影响](/encrypted-resource-id)理解降低可枚举性的思路，资源访问的授权仍需独立校验。需要在应用内部感知和干预运行行为时，继续阅读[安全平行切面](/aop-security)。

应用开始读取外部内容、检索知识或调用模型后，从[大模型应用安全](/llm-application-security)检查上下文与输出的信任边界；[模型安全：对齐与输出安全](/ai-model-alignment-output-security)说明模型行为改善的作用与边界。完整控制设计由 [AI 系统安全](/ai-system-security)导读串联。

## 数据与凭据

处理员工文档外发、个人设备接触公司资料和非工作用途查询时，参考[办公安全](/office-security)中的数据流动与权限使用场景。发现密码或 Token 已进入代码仓库时，转到[GitHub 敏感信息泄露处置](/github-sensitive-data-response)，核对凭据撤销、影响调查与副本清理。

保护 AI 系统的数据与制品时，[AI 数据与知识安全](/ai-data-knowledge-security)检查知识、记忆和反馈的来源及撤销，[AI 隐私与机密保护](/ai-privacy-confidentiality)跟进数据及派生物的用途、留存和删除。[AI 核心资产与基础设施安全](/ai-crown-jewels-infrastructure-security)与[模型资产与 AI 供应链安全](/ai-model-supply-chain-security)分别讨论核心资产保护，以及模型制品、依赖和发布版本的可信性。

## 终端与办公

面对邮件钓鱼、附件、链接和邮箱账号风险，从[电子邮件安全实践](/email-security)查找个人与组织侧的防护方法。涉及办公设备、远程访问和日常资料流转时，结合[员工侧方案](/gugu)与[办公安全](/office-security)核对访问渠道和设备边界。支付设备与 Agent 进入业务的历史实践，可参考[数智时代支付新安全](/redefining-payment-security-in-the-ai-era)，其中的阶段判断按演讲时的背景理解。

## 监测与响应

跨系统日志关联、告警研判和应急协作，先从[安全体系中的威胁感知响应](/security-system#威胁感知响应)理解各环节的关系；运行对象包含 Agent 时，继续阅读[AI 运行监控与事件响应](/ai-security-monitoring-response)，核对输入、上下文、工具调用与业务副作用的记录，以及停止、恢复和复盘要求。

防御措施上线或发生变更后，进入[安全实战检验](/security-drill)核对验证方法；AI 系统的版本证据与对抗评测要求见[AI 系统安全评测与红队](/ai-security-evaluation-red-teaming)。
