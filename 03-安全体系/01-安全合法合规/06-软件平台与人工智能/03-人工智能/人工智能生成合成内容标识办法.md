# 人工智能生成合成内容标识办法

标识义务应分别落实到生成、导出、传播与应用分发环节，并保留适用例外。本文依据[国信办通字〔2025〕2号正式文本](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)，工程测试为实施建议。

[法规概览](#overview) · [安全要求与实施](#requirements) · [法规原文](#reference)

## 法规概览 {#overview}

| 项目 | 内容 |
| --- | --- |
| 印发与施行 | 2025年3月7日印发，2025年9月1日施行 |
| 适用对象 | 符合算法推荐、深度合成、生成式人工智能相关规定情形的网络信息服务提供者 |
| 标识类型 | 显式标识便于用户感知；隐式标识通过技术方式写入文件数据 |
| 主要角色 | 生成合成服务、内容传播服务、应用分发平台及发布内容的用户 |
| 组合要求 | 同时核对深度合成等相关规定和适用强制性国家标准 |

## 安全要求与实施 {#requirements}

### 在应标场景添加显式标识

**法规要求｜第4条。** 属于深度合成规定第17条第一款情形的生成合成服务，按文本、音频、图片、视频、虚拟场景等载体添加相应显式标识；提供下载、复制和导出时，还应确保文件中含有满足要求的标识。第9条的条件例外另行管理。

**实施。** 对内容类型、交互界面、下载文件、API和批量导出分别确认适用方式。界面提示不能自动替代输出文件要求，也不能将所有模态统一简化成在页面角落显示“AI”二字。

**验收。** 同一测试内容分别经过网页、App、API、下载和分享，检查适用位置、可感知性和正常处理后是否保持有效。新增渠道或转码库升级时重跑测试，记录生成版本与标识结果。

### 隐式标识区分制作要素和传播要素

**法规要求｜第5—6条。** 制作环节按要求写入生成合成属性、服务提供者名称或编码、内容编号等元数据。传播环节对相应情形增加属性、传播平台名称或编码、内容编号等传播要素。数字水印等额外方式属于鼓励措施，不能与规定的元数据要求混为一项。

| 环节 | 实施建议 | 核验方法 |
| --- | --- | --- |
| 制作 | 将元数据写入生成和导出流水线 | 独立读取输出文件，核对制作要素及内容关联 |
| 传播 | 保留识别结果并按适用情形写入传播要素 | 上传、转码、分发后再次读取元数据 |
| 失败处理 | 标识写入失败告警并受控处置 | 注入写入失败，验证不会静默绕过既定控制 |
| 变更回归 | 覆盖媒体库、文件格式及第三方渠道 | 比较升级前后同一组测试文件 |

具体字段编码和文件格式应对照适用强制性国家标准；自定义一个JSON标签不能未经核验就宣称符合要求。

### 内容传播按三类证据分别提示

第6条区分元数据明确标识、用户声明及检测到其他生成痕迹。平台需要保留判断来源，不能把三种情况都展示为已经确定的AI生成结论。

| 识别依据 | 提示口径 | 后续动作 |
| --- | --- | --- |
| 元数据明确标明生成合成 | 明确提示属于生成合成内容 | 添加适用传播要素 |
| 未发现隐式标识，但用户声明 | 提示可能为生成合成内容 | 添加适用传播要素 |
| 无隐式标识及用户声明，但检测到显式标识或其他痕迹 | 提示疑似生成合成内容 | 添加适用传播要素 |

平台还应提供必要标识功能并提醒用户主动声明。验收覆盖外部平台文件、用户自行声明、部分元数据缺失和误标申诉；不能以内容非本平台生成为由排除传播义务。

### 用户申请无显式标识的条件例外

**法规要求｜第9条。** 用户提出申请后，服务提供者可以通过用户协议明确其标识义务和使用责任，再提供不含显式标识的内容，并依法保存提供对象信息等相关日志至少六个月。

**适用边界。** 该条针对显式标识，不等于允许取消第5条隐式标识或免除用户发布时的声明和标识义务。依法依条件提供无显式标识内容，也不应被直接认定为恶意去标识。

**实施与验收。** 为例外请求记录申请人、适用协议版本、责任提示、内容编号和提供时间；独立验证文件仍满足适用隐式标识要求，以及相关日志生命周期不少于六个月。没有申请和协议依据的默认无标导出，不应借用这条例外。

### 恶意去标识、应用分发与程序材料

**法规要求｜第7—8、10—12条。** 用户发布时主动声明并使用标识功能；不得恶意删除、篡改、伪造、隐匿法定标识，也不得为相应恶意行为提供工具或服务。服务协议应明确标识方法、样式及管理要求；应用分发平台核验提供相关服务的App标识材料；备案和安全评估等手续还需提供相应材料。

**验收。** 将生成、文件处理、重新发布、例外导出和应用上架连接到同一测试矩阵。检查产品是否提供绕过规则的默认路径；对普通编辑、技术故障、依法适用例外和恶意规避分别判断，避免简单扩大禁止范围或漏掉明确恶意场景。

## 一次完整验收

以一段测试内容穿行生成、下载、合法例外申请、上传他平台和再次传播。检查界面和文件标识、制作及传播元数据、用户声明、例外协议和日志，并验证转码或写入失败时的处置。

通过条件是每个角色在其适用范围内完成义务，例外有条件和证据，标识来源与提示口径一致。不能仅以“下载样本带水印”推导整个服务已经合规。
