# 互联网信息服务算法推荐管理规定

本文把算法推荐治理转成企业可执行的算法资产、机制审核、内容治理、用户权益、特殊群体保护、备案与安全评估等控制。判断重点不是“是否用了AI”，而是是否利用生成合成、个性化推送、排序精选、检索过滤、调度决策等算法技术向用户提供互联网信息服务。

[法规概览](#overview) · [安全要求与实施](#requirements) · [法规原文](#reference)

## 法规概览 {#overview}

| 项目 | 内容 |
| --- | --- |
| 法规 | 《互联网信息服务算法推荐管理规定》（第9号令） |
| 生效日期 | 2022年3月1日 |
| 主要适用对象 | 在境内应用算法推荐技术提供互联网信息服务的提供者 |
| 算法范围 | 生成合成、个性化推送、排序精选、检索过滤、调度决策等 |
| 关键硬约束 | 特定主体算法备案10个工作日；变更10个工作日；终止服务20个工作日注销；备案编号显著公示 |
| 官方来源 | [国家互联网信息办公室](https://www.cac.gov.cn/2022-01/04/c_1642894606364259.htm) |

下文按 **“法规要求 → 落实与验收”** 展开：每项要求同时说明实施动作与可验证证据。算法同时涉及个人信息、内容、未成年人、深度合成、生成式AI等场景时，应并行满足相应专项规则。

## 安全要求与实施 {#requirements}

| 核心主题 | 达成状态 |
| --- | --- |
| 算法资产与适用性 | 知道线上有哪些算法、用途、责任人以及触发哪些义务 |
| 算法机制审核 | 模型、数据、规则和结果持续评估，不只上线前评一次 |
| 内容与呈现治理 | 推荐、搜索、热榜等关键链路可识别和处置违法不良信息 |
| 用户权益 | 用户知道在使用算法，能关闭个性化并管理个人标签 |
| 特殊群体与场景 | 未成年人、老年人、劳动者、消费者专项权益进入算法设计 |
| 备案与安全评估 | 应备案、应变更、应注销、应安全评估的服务不会遗漏 |

### 建立完整算法资产和适用性判断

**法规要求｜第2、7、23条。** 算法推荐包括生成合成、个性化推送、排序精选、检索过滤、调度决策等技术；提供者应落实算法安全主体责任，并按算法服务属性接受分级分类管理。

**落实与验收。**
- 建立线上算法清单，关联产品功能、算法类型、模型/规则版本、数据来源、用户范围、责任人、是否具有舆论属性或社会动员能力等信息。
- 新算法、新场景、重大模型升级和推荐逻辑变化进入合规评审，不能只管理机器学习模型而遗漏规则排序、搜索过滤和调度算法。
- 把算法资产与备案、安全评估、个人信息、内容治理等义务映射，变化时自动触发重新判断。

**验收证据。**
- 从线上首页、搜索、推荐流、榜单、派单等功能反查算法清单，是否存在真实运行但治理台账不知道的算法？
- 随机抽一个规则排序系统，团队是否因为“不是AI模型”而认为不属于算法治理？
- 从最近半年模型/策略发布记录反查，重大变更是否都经过适用性和风险判断？

### 定期审核算法机制、模型、数据和应用结果

**法规要求｜第7—8条。** 应建立算法机制机理审核、科技伦理审查、安全评估监测等制度和技术措施，定期审核、评估、验证算法机制机理、模型、数据和应用结果，不得设置诱导沉迷、过度消费等违法违规或违背伦理道德的模型。

**落实与验收。**
- 上线前明确目标函数、主要特征、训练/评估数据、干预机制、风险边界和回滚方案。
- 上线后持续监测分布漂移、异常放大、沉迷/消费诱导、偏差和用户投诉等结果风险。
- 重大算法变更重新评估，科技伦理、安全和业务风险不能用一次性上线审批永久覆盖。
- 风险指标超过阈值时具备降级、关闭个性化、人工干预或回滚能力。

**验收证据。**
- 随机抽一个核心推荐算法，现场拿出最近一次机制审核、结果评估和问题整改，而不是只有模型说明书。
- 人为制造高互动但高风险内容，测试系统是否会因点击率目标持续放大推荐。
- 找一个最近发生重大策略变化的算法，原风险评估是否重新执行？
- 查看异常指标触发后是否真的发生过降级或人工干预，而不是预案里“可以”。

### 控制内容、标签和重点页面呈现

**法规要求｜第9—14条。** 应建立违法和不良信息特征库，加强用户模型、用户标签和版面页面生态管理；不得利用算法操纵账号、虚假互动、榜单、检索结果、热搜等实施影响网络舆论或者规避监管的行为。

**落实与验收。**
- 内容审核能力覆盖算法输入、候选集、排序结果和最终呈现，违法内容能够停止传输、消除影响、留存记录并按要求报告。
- 用户兴趣点和标签有准入、更新、删除和敏感风险控制，不把违法不良信息关键词作为推荐依据。
- 首页首屏、热搜、精选、榜单、弹窗、搜索等重点位置建立人工干预和异常操纵监测。
- 刷量、刷榜、虚假点赞评论、操纵排序等行为进入反作弊治理。

**验收证据。**
- 给测试账号持续浏览边界/不良内容，观察标签和推荐是否不断强化形成风险闭环。
- 从热搜或榜单历史数据抽取一次异常跃升，能否解释来源、干预和反作弊判断？
- 对已确认违法内容反查推荐、搜索、榜单等所有传播链路，是否只删原帖但仍能通过算法继续传播？
- 抽取用户标签，是否存在违法不良关键词或无法解释来源的敏感标签？

### 让用户真正拥有知情权和选择权

**法规要求｜第16—17条。** 应显著告知提供算法推荐服务的情况，公示基本原理、目的意图和主要运行机制；提供不针对个人特征的选项或者便捷关闭算法推荐的选项，并提供选择或删除个人标签的功能。

**落实与验收。**
- 在用户容易看到的位置说明算法推荐，而不是仅埋在长篇隐私政策中。
- 关闭个性化后，推荐链路实际停止使用个人特征，而不是只改变前端开关状态。
- 用户能够查看、选择或删除用于推荐的个人标签，删除后下游特征和推荐服务同步生效。
- 算法对用户权益造成重大影响时具备可说明机制和人工申诉渠道。

**验收证据。**
- 新用户是否能在正常使用路径中知道自己正在接受算法推荐？
- 关闭个性化后抓取请求和后端特征调用，个人画像是否仍参与排序？
- 删除一个兴趣标签后重新使用服务，该标签是否仍继续影响推荐？
- 用户对重大算法结果申诉时，客服能否解释原因并转入人工复核？

### 对特殊群体和高影响场景设置专项控制

**法规要求｜第18—21条。** 对未成年人、老年人、劳动者和消费者分别提出保护要求，包括防沉迷、适老与反诈、劳动调度权益以及禁止不合理差别待遇等。

**落实与验收。**
- 未成年人算法策略与年龄识别联动，限制可能诱导沉迷或影响身心健康的推荐。
- 老年人高风险场景强化反诈识别和适老设计。
- 派单、报酬、工作时间、奖惩等劳动调度算法保留规则解释、测试和人工纠偏机制。
- 定价、优惠、排序等消费者算法持续检测是否因画像或交易习惯产生不合理差别待遇。

**验收证据。**
- 使用未成年人账号和成年人账号跑相同内容路径，推荐结果和沉迷控制是否真实不同？
- 对同一商品使用不同画像账号测试价格和交易条件，差异是否有合理、可解释依据？
- 随机抽取骑手/司机等一次异常派单或处罚申诉，能否还原算法规则和人工复核过程？
- 老年用户是否更容易被高风险营销或诈骗内容命中，监测指标是否单独观察？

### 把备案和安全评估做成生命周期控制

**法规要求｜第24—28条。** 具有舆论属性或者社会动员能力的算法推荐服务提供者，应在提供服务之日起10个工作日内备案；信息变更后10个工作日内变更，终止服务后20个工作日内注销；完成备案后显著标明备案编号；并按规定开展安全评估、配合监督检查。

**落实与验收。**
- 产品立项时判断是否具有舆论属性或者社会动员能力，并把结论与依据留档。
- 应备案服务在上线计划中设置10个工作日时限控制，备案信息与实际算法、产品和主体保持一致。
- 模型、用途、服务形式等备案信息发生变化时触发变更判断；下线时触发注销。
- 备案编号在网站/App显著位置公示，并维护安全评估、网络日志和监管检查材料。

**验收证据。**
- 从线上具有推荐能力的产品反查算法备案清单，是否存在应备案未备案的服务？
- 随机抽一个已备案算法，将备案中的服务形式、算法类型、应用领域与当前生产版本逐项比对。
- 找一个最近发生重大变更或下线的算法，10/20个工作日的变更或注销时限是否实际满足？
- App/网站上的备案编号是否真实可见、可查询，而不是只有内部备案截图？
