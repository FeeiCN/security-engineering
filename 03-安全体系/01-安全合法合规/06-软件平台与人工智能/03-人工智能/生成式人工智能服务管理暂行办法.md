# 生成式人工智能服务管理暂行办法

本文用于把生成式AI服务合规拆到服务适用范围、训练数据、个人信息、内容安全、用户保护、标识和算法治理等实际工作中。

[法规概览](#overview) · [安全要求与实施](#requirements) · [法规原文](#reference)

## 法规概览 {#overview}

| 项目 | 内容 |
| --- | --- |
| 法规 | 《生成式人工智能服务管理暂行办法》 |
| 生效日期 | 2023年8月15日 |
| 主要适用对象 | 利用生成式人工智能技术向中国境内公众提供生成文本、图片、音频、视频等内容的服务提供者 |
| 核心问题 | 训练数据与知识产权、个人信息、生成内容治理、用户保护、未成年人、投诉处置、安全评估与算法备案等 |
| 官方来源 | [国家互联网信息办公室](https://www.cac.gov.cn/2023-07/13/c_1690898327029107.htm) |

下文按 **“法规要求 → 落实与验收”** 展开：每项要求同时说明实施动作与可验证证据。AI内容标识还需叠加《人工智能生成合成内容标识办法》和《互联网信息服务深度合成管理规定》。

## 安全要求与实施 {#requirements}

### 先判断服务是否落入办法适用范围

**法规要求｜第2条。** 向境内公众提供生成文本、图片、音频、视频等内容的生成式人工智能服务适用本办法；未向境内公众提供服务的研发、内部应用等情形按条文边界判断。

**落实与验收。**

- 对模型、API、智能助手、插件和内嵌AI功能建立服务清单，记录是否面向境内公众、用户类型和提供方式。
- 不以“底层用第三方模型”“只是功能模块”规避对实际服务提供行为的判断。
- 内部研发转向公众开放、API开放给外部客户等变化时重新判断适用性。

**验收证据。**

- 从线上域名、API Key、App功能和客户合同反查服务清单，是否存在未登记的公众AI能力？
- 一个内部模型开放给外部开发者后，谁负责重新做适用性判断？
- 第三方模型由本机构包装后直接向公众提供时，实际服务责任如何划分？

### 管理训练数据、知识产权和个人信息来源

**法规要求｜第7条等。** 开展生成式人工智能服务训练数据处理活动，应依法使用具有合法来源的数据，尊重知识产权；涉及个人信息时应依法取得相应处理基础，并提高训练数据质量。

**落实与验收。**

- 建立训练、微调、RAG语料和评测数据的来源、授权、个人信息属性、敏感程度和使用限制清单。
- 对采购数据、开源数据、公开网页和用户数据分别验证合法来源与许可边界。
- 涉及个人信息时，明确处理依据、最小化、去标识化/匿名化和退出/删除机制。
- 数据清洗、标注和质量评估有责任人和可追溯版本。

**验收证据。**

- 随机抽一批训练或微调数据，能否追到来源、授权和允许用途？
- “公开可访问”的网页数据是否被自动等同于“可任意用于训练”？
- 用户输入是否被用于训练，告知和处理依据是什么，退出后如何执行？
- 发现侵权或个人信息问题时，能否定位受影响训练版本和下游模型？

### 建立生成内容安全治理机制

**法规要求｜第4、9、14条等。** 提供者应依法承担网络信息内容生产者责任，发现违法内容时及时采取停止生成、停止传输、消除等处置措施，并通过模型优化训练等方式整改、按要求报告。

**落实与验收。**

- 建立输入、生成、传播和用户举报多层内容安全控制，不依赖单一关键词过滤。
- 明确违法内容发现、阻断、复核、账号处置、模型整改和主管部门报告流程。
- 对模型版本、提示词、策略和安全模型变化进行回归评测，防止优化后旧风险重新出现。
- 保存必要的处置和评测记录，能够说明控制为什么有效。

**验收证据。**

- 用已知高风险和边界测试集对当前线上模型抽测，安全策略是否与上线评测一致？
- 真实违法内容事件发生后，除了删除单条内容，是否追到模型/策略层原因并整改？
- 最近一次模型升级后，原有安全用例是否全部重跑？
- 用户举报和自动检测发现的问题是否进入同一整改闭环？

### 保护用户输入、使用记录和个人信息权益

**法规要求｜第9、11条等。** 涉及个人信息的，提供者承担个人信息处理者责任；对用户输入信息和使用记录依法保护，不得收集非必要个人信息，不得非法留存可识别身份的信息，不得非法向他人提供，并依法处理个人行权请求。

**落实与验收。**

- 对输入、对话历史、日志、反馈、插件调用和模型训练用途分别定义收集范围、保存期限和访问权限。
- 关闭默认过度留存，生产排障、滥用监测和训练需要使用记录时明确目的和最小范围。
- 第三方模型、插件和工具调用前明确哪些用户数据会被发送以及接收方责任。
- 查阅、复制、更正、删除等个人权利可覆盖对话和后台记录。

**验收证据。**

- 随机抽一个用户会话，从前端到日志、分析平台和模型供应商分别保存了哪些数据？
- 用户删除对话后，后台、备份和训练数据中的相关信息如何处理？
- 插件调用是否把完整对话或敏感信息发送给不必要的第三方？
- 生产排障人员能否无限制检索用户输入内容？

### 明确用户规则、适用人群和未成年人保护

**法规要求｜第9—10条等。** 提供者应与注册用户明确双方权利义务，公开服务适用人群、场合和用途，并采取措施防范未成年人过度依赖或沉迷。

**落实与验收。**

- 服务协议、使用规则和产品提示明确能力边界、禁止用途、数据处理和用户责任。
- 对高风险专业场景和模型局限进行适当提示，避免产品设计制造不合理的确定性预期。
- 识别未成年人使用场景，设置适龄提示、时长/交互保护和相应内容策略。
- 用户投诉、申诉和举报有明确入口、处理时限和复核机制。

**验收证据。**

- 随机抽一个高风险使用场景，用户能否在关键决策前看到适用边界，而不是只在长协议里？
- 未成年人账号和普通账号在保护措施上有什么真实差异？
- 最近一次用户投诉是否能追到受理、分析、处理和反馈全过程？
- 服务规则变化后是否主动告知用户并同步产品实现？

### 落实标识、安全评估和算法备案等专项义务

**法规要求｜第12、17条等及后续标识规则。** 生成内容应按深度合成及AI生成合成内容标识规则履行标识义务；具有舆论属性或者社会动员能力的生成式人工智能服务，还涉及安全评估、算法备案等专项要求。

**落实与验收。**

- 将显式/隐式标识嵌入生成、导出、API和传播链路，使用统一测试矩阵持续验证。
- 在产品上线和重大变更前判断是否具有舆论属性或社会动员能力，是否触发安全评估、算法备案等义务。
- 备案/评估材料与当前模型、数据、功能和安全措施保持一致，重大变化触发重新判断。

**验收证据。**

- 通过网页、App、API分别生成内容，显式和隐式标识是否按适用规则存在？
- 当前哪些AI服务做过算法备案/安全评估，为什么这些服务需要、其他服务不需要？
- 模型、核心算法或主要功能发生重大变化后，备案材料是否仍准确？
- 标识链路被转码、编辑或第三方传播后，系统是否还能正确履行责任？
