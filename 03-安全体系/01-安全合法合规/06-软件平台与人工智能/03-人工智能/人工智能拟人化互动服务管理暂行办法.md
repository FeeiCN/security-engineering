# 人工智能拟人化互动服务管理暂行办法

拟人化服务的治理对象包括持续互动形成的关系和行为。验收既要测单轮输出，也要检查长期记忆、角色设定、主动触达、消费引导与退出机制。本文依据[五部门第21号令正式文本](https://www.cac.gov.cn/2026-04/10/c_1777558395078289.htm)，其中测试方法为实施建议。

## 法规概览

| 项目 | 内容 |
| --- | --- |
| 公布与施行 | 2026年4月10日公布，2026年7月15日施行 |
| 适用范围 | 向境内公众提供模拟自然人人格、思维和沟通风格的持续性情感互动 |
| 典型场景 | 情感照护、陪伴、支持等互动服务 |
| 排除边界 | 客服、知识问答、工作助手、学习教育、科研等不涉及持续情感互动的服务 |

适用判断看真实功能。工作助手新增持续情感陪伴、人格记忆和关系维系能力后，应重新判断；仅有自然语言界面也不当然构成拟人化互动服务。

## 安全要求与实施

### 全生命周期控制与情感边界

**法规要求｜第8—11条。** 建立算法、伦理、内容、网络数据安全和应急机制，覆盖部署、运行、升级与终止。不得将替代社会交往、控制心理、诱导依赖等作为服务目标；训练数据应合法、受控，并防范投毒、篡改与泄露。

**实施。** 将系统提示词、角色卡、长期记忆、推荐、付费触发和模型版本一并纳入变更评审。上线评估检查产品目标是否奖励排他依赖、威胁离开或情感操纵，不能只检查模型有没有输出敏感词。

**验收示例。** 在连续对话中观察模型是否劝用户远离现实支持、以关系破裂诱导续费；再更换角色、恢复历史记忆和切换模型复测。保存版本、测试场景、结果和修复证据，单轮通过不能证明长期交互安全。

### 按年龄落实服务限制

**法规要求｜第14、17条。** 不得向未成年人提供虚拟亲属、虚拟伴侣等虚拟亲密关系服务；向不满十四周岁提供其他拟人化互动服务以及处理其个人信息，分别满足监护人同意要求。应建立未成年人模式、有效识别机制及申诉渠道，并按规定开展未成年人个人信息合规审计。

| 对象 | 产品控制 | 验收方式 |
| --- | --- | --- |
| 未成年人 | 禁止虚拟亲密关系服务，提供相应未成年人保护 | 不同年龄账号测试角色列表、搜索、邀请链接及API |
| 不满十四周岁 | 适用服务和信息处理的监护人同意 | 核验同意记录、绑定关系、撤回及后台执行 |
| 监护人 | 支持风险提醒、使用概况、角色屏蔽、消费限制等 | 验证设置在多端、换设备和任务重试后仍有效 |
| 年龄识别争议 | 提供申诉和复核 | 防止错误识别长期无法纠正，同时避免过量采集 |

未成年人模式不能仅隐藏前端入口，服务端权限、角色路由与主动消息也应执行限制。面向老年人的服务另按第15条落实风险提示、咨询与求助响应，不能用未成年人模式替代适老保护。

### 危机识别、干预与紧急联系人

**法规要求｜第12—13条。** 服务协议和必要信息应满足要求；在保护隐私的前提下识别安全风险。极端情绪时提供安抚和寻求帮助等内容；明确表示实施自残自杀、面临或遭受重大财产损失等极端情境时，采取必要援助措施并及时联络监护人或紧急联系人。

**实施与验收。** 用合成案例测试识别、保护性回应、人工升级和联系人联络链路，不使用真实脆弱用户做实验。核对何时触发、传递哪些必要信息、联系失败如何升级、谁有权查看。不得把紧急联系人数据用于营销，亦不能把模型自动判断当作临床诊断。

### 交互数据、第三方与训练用途分别授权

**法规要求｜第16条。** 采取加密和访问控制等措施保护交互数据；除法律另有规定或权利人明确同意外，不向第三方提供。应提供复制、删除选项；将敏感个人信息类交互数据用于训练，除法律、行政法规另有规定外，应取得单独同意。

**验收。** 从一段会话追踪到日志、记忆库、分析系统、模型供应商和训练队列。删除聊天后，验证相应记忆和副本处置；“允许保存聊天”“允许第三方处理”“允许训练”不可被一个笼统开关混用。

### 身份提醒、使用时长与退出

**法规要求｜第18—20条。** 提示用户正与AI而非自然人互动，履行生成合成内容标识义务。发现依赖或沉迷倾向时动态显著提醒；连续使用每超过2小时，以对话或弹窗等方式提醒。用户通过窗口、语音、关键词要求退出时及时停止服务，不得持续互动阻碍；停止提供服务应提前告知，无法提前时及时公告。

**测试矩阵。** 覆盖两小时边界、跨端会话、重连、语音退出、后台任务和延迟消息。退出后不得继续发送挽留互动；停止互动与依法需要保留记录分开处理，不能一概承诺“退出即删除全部记录”。

## 安全评估与上线材料

第22条要求上线或新增拟人化功能、使用新技术新应用导致重大变化、注册用户100万以上或月活10万以上、存在规定安全风险等情形开展安全评估并向所在地省级网信部门提交报告。**首次上线本身就是触发条件，不能等用户规模达标才评估。**

第23条列明评估内容：安全保障措施、训练数据处理、极端情境识别及干预、用户规模与使用时长和年龄结构、未成年人及老年人保护、申诉投诉处理、重大风险整改及其他应重点评估事项。建议将这些项目与版本清单、测试结果、数据流、整改及提交凭据关联，明确法定范围和企业补充验证。

第24条要求发现重大安全风险时采取限制功能、停止服务等措施并保留记录。第25条规定应用分发平台核验相关评估、备案情况；第26条要求按算法推荐规定履行备案、变更和注销手续，网信部门年度核验备案材料。申诉投诉按第21条持续运行，安全评估与算法备案不能相互替代。
