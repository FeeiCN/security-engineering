# 常见类型移动互联网应用程序必要个人信息范围规定

本文把“必要个人信息范围”从一张法规清单转成产品、隐私和安全团队可以直接执行的最小必要控制。核心判断只有一个：**如果用户拒绝提供某项信息，App 的基本功能是否真的无法实现？** 如果仍然可以实现，就不能仅为了推荐、增长、风控便利或运营分析把它包装成基本功能的必要信息。

[法规概览](#overview) · [安全要求与实施](#requirements) · [39类App必要范围速查](#catalog) · [法规原文](#reference)

## 法规概览 {#overview}

| 项目 | 内容 |
| --- | --- |
| 法规 | 《常见类型移动互联网应用程序必要个人信息范围规定》 |
| 生效日期 | 2021年5月1日 |
| 适用对象 | 移动智能终端App，也包括符合定义的小程序 |
| 核心概念 | 必要个人信息是保障基本功能正常运行所必需、缺少即无法实现基本功能的消费侧用户个人信息 |
| 核心要求 | 不得因为用户不同意提供非必要个人信息，而拒绝其使用基本功能服务 |
| 覆盖范围 | 39类常见App基本功能及必要个人信息范围 |

下文按 **“法规要求 → 落实与验收”** 展开：每项要求同时说明实施动作与可验证证据。本规定给出的是基本功能的必要范围，不意味着范围内信息在任何时点都可以无条件收集；具体处理仍需叠加《个人信息保护法》及权限、敏感个人信息等专项要求。

## 安全要求与实施 {#requirements}

### 先确定App属于哪一类、基本功能是什么

**法规要求｜第2—5条。** App应按其实际基本功能判断必要个人信息；规定列明39类常见App的基本功能和必要范围。

**落实与验收。**

- 每个App、小程序建立“产品功能 → 法规App类型 → 基本功能 → 必要个人信息”映射。
- 一个产品同时包含支付、购物、社区等多类功能时分别判断，不能因为产品整体属于某一类型就把所有信息都认定为全局必要。
- 新增业务类型或基本功能发生实质变化时重新评估，而不是沿用首次上线时的结论。
- 无法落入39类的功能仍按最小必要原则和其他个人信息保护规则单独论证，不反向推导为“法规没写所以都能收”。

**验收证据。**

- 随机抽一个多功能App，让产品负责人现场画出各基本功能与必要信息映射，是否把增值功能信息混进基本功能？
- 从线上功能反查分类结论，是否存在产品已经新增金融、社区等能力但隐私分类多年未更新？
- 对每个被标为“必要”的字段追问：删除它后基本功能具体在哪一步无法完成？

### 把必要性落实到真实采集时点和产品交互

**法规要求｜第3—4条。** 必要个人信息应是缺少即无法实现基本功能的信息；用户不同意提供非必要个人信息时，不得拒绝其使用基本功能。

**落实与验收。**

- 个人信息在实际需要该功能时再收集，不因为未来可能使用而在首次启动时一次性索取。
- 将“必要/非必要”结论落实到客户端权限、表单必填项、接口参数、SDK配置和服务端校验，而不是只写在隐私政策里。
- 非必要信息拒绝、权限拒绝、撤回同意后，基本功能应继续可用。
- 推荐、广告、用户画像、增长分析等附加目的与基本功能解耦，不能通过阻断登录、浏览、支付等方式变相强迫同意。

**验收证据。**

- 全新安装App，逐项拒绝非必要权限和授权，基本功能是否仍可完整走通？
- 抓包检查：界面上未要求的信息是否被SDK、设备接口或服务端静默采集？
- 将某个非必要字段留空，接口是否因后端参数校验直接拒绝整个基本功能？
- 撤回定位、通讯录等授权后，除对应增值功能外是否出现无关功能不可用？

### 建立“法规上限—业务实际—代码实现”三方对账

**法规要求｜第4—5条。** 对列明的App类型，基本功能必要信息不得被任意扩大；部分类型明确基本功能无需个人信息即可使用。

**落实与验收。**

- 建立机器可维护的数据字段清单，至少包含字段、来源、目的、功能、必要性、采集时点、保存期限、共享对象和法规依据。
- 将法规允许的必要范围作为上限基线，与隐私政策、产品PRD、权限配置、SDK清单和真实网络流量定期对账。
- 对“法规范围内但当前业务实际不需要”的字段不默认收集；法规范围不是必须收集清单。
- 对超出必要范围但有其他合法处理依据的信息明确标记为非必要，并提供相应选择权。

**验收证据。**

- 从真实流量中抽10个个人信息字段，能否全部回到数据清单并解释功能、目的和必要性？
- 从法规必要范围反查代码：是否存在“法规允许，所以顺手都采了”的字段？
- 从隐私政策声明反查实际接口，是否存在政策写了但产品从不使用，或产品在收但政策没写？
- 对版本升级前后做字段diff，新增采集是否自动触发隐私评审？

### 对“无需个人信息即可使用”的App做零信息基线测试

**法规要求｜第5条。** 女性健康、网络直播、在线影音、短视频、新闻资讯、运动健身、浏览器、输入法、安全管理、电子图书、拍摄美化、应用商店、实用工具等多类App的规定基本功能无需个人信息即可使用。

**落实与验收。**

- 对法规明确“无须个人信息”的基本功能建立零信息启动和使用基线。
- 账号体系、个性化、云同步、评论等增值能力可以另行判断，但不能成为浏览、播放、拍摄等基本功能的强制前置条件。
- 设备标识符、广告标识符、精确位置等后台采集同样属于测试范围，不能只检查用户主动填写字段。

**验收证据。**

- 未登录、不同意非必要处理、不给任何可选权限，能否完成法规定义的基本功能？
- 抓取冷启动流量，是否在用户没有使用增值功能前就上传设备标识、位置或其他个人信息？
- 断开账号体系后，视频播放、新闻浏览、拍摄等基本能力是否被人为关闭？

## 法规原文 {#reference}

完整39类App的法定必要个人信息范围以原文逐项核对，尤其是支付、金融、医疗、出行等字段较多的类型。
