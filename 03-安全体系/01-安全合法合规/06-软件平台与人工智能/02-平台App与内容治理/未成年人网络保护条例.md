# 未成年人网络保护条例

本文依据国务院令第766号《未成年人网络保护条例》整理。条例自2024年1月1日起施行，覆盖网络素养促进、网络信息内容规范、未成年人个人信息网络保护和网络沉迷防治等要求。

[法规概览](#overview) · [安全要求与实施](#requirements) · [法规原文](#reference)

## 法规概览 {#overview}

| 项目 | 内容 |
| --- | --- |
| 法规 | 《未成年人网络保护条例》（国务院令第766号） |
| 生效日期 | 2024年1月1日 |
| 主要适用对象 | 网络产品和服务提供者、个人信息处理者、智能终端产品制造者和销售者，以及其他与未成年人网络活动相关主体 |
| 核心问题 | 内容分级与处置、网络欺凌、未成年人个人信息、未成年人模式、消费限制、防沉迷、投诉举报 |
| 官方来源 | [中国政府网](https://www.gov.cn/zhengce/content/202310/content_6911288.htm) · [中国网信网](https://www.cac.gov.cn/2023-10/24/c_1699806932316206.htm) |

下文按 **“法规要求 → 落实与验收”** 展开：每项要求同时说明实施动作与可验证证据。对于未成年人个人信息，还需同步遵守《个人信息保护法》等规定；对于游戏、直播、音视频、社交等具体业务，还应叠加相应行业专项规则。

## 安全要求与实施 {#requirements}

| 核心主题 | 达成状态 |
| --- | --- |
| 未成年人识别与场景判断 | 能识别未成年人用户及高风险业务场景 |
| 内容保护 | 危害或影响未成年人身心健康的信息能分级、提示、限制和处置 |
| 个人信息保护 | 未成年人信息采集、访问、共享和删除受到更严格控制 |
| 未成年人模式与防沉迷 | 时段、时长、功能、内容和消费限制可实际生效 |
| 网络欺凌与互动安全 | 欺凌、诱导、恶意互动有识别和保护机制 |
| 投诉举报与监督 | 监护人和未成年人能便捷投诉、申诉并获得反馈 |

### 先识别哪些用户和功能属于未成年人保护范围

**法规要求｜第6、31条等。** 网络产品和服务提供者、个人信息处理者等主体承担未成年人网络保护义务；提供信息发布、即时通讯等服务时，应依法要求未成年人或者其监护人提供真实身份信息。

**落实与验收。**

- 形成未成年人相关产品、功能和数据清单，至少覆盖账号、社交、直播、游戏、音视频、内容发布、付费和推荐场景。
- 身份与年龄识别采用与风险匹配的方式，不能完全依赖用户自填年龄后不再验证。
- 未识别年龄但具有明显未成年人高风险特征的场景，应有保守保护策略。
- 未成年人身份信息与普通业务画像分开控制，避免为了保护目的反而扩大采集范围。

**验收证据。**

- 随机选择一个具有社交或付费能力的产品，是否知道用户是否为未成年人？
- 用户修改年龄、换设备、换账号后，保护策略是否容易被绕过？
- 是否存在“只要用户没主动声明未成年，就按成年人处理”的默认逻辑？
- 年龄识别采集的数据是否超过实现保护目的所必需范围？

### 建立面向未成年人的内容分级、提示和处置机制

**法规要求｜第三章相关条款。** 对危害未成年人身心健康的信息不得向未成年人传播；对可能影响未成年人身心健康的信息，应当以显著方式作出提示。平台发现相关违法或有害信息时，应按规定采取停止传输、删除、屏蔽、断开链接等措施并保存记录。

**落实与验收。**

- 建立未成年人内容风险分类标准，并与通用违法不良信息标准区分管理。
- 推荐、搜索、热榜、评论、弹幕、私信、直播和群组等所有内容入口统一接入保护策略。
- 对“可能影响”而非绝对禁止的信息建立年龄适配、显著提示和推荐限制能力。
- 对模型识别、用户举报和人工审核的命中结果建立统一处置记录和复核机制。

**验收证据。**

- 在未成年人账号下搜索或推荐高风险关键词，结果是否与成年账号存在合理差异？
- 风险内容从“发布成功”到“发现并处置”平均需要多久？
- 已被删除的内容能否通过转发、截图OCR、变体词、镜像链接重新传播？
- 对“限制推荐”类内容，是否只是打标签但仍可进入热榜和相关推荐？

### 对未成年人个人信息实施更严格的最小权限和生命周期控制

**法规要求｜第四章。** 处理未成年人个人信息应遵循合法、正当、必要和诚信原则，采取严格保护措施。对工作人员访问未成年人个人信息应按照最小授权原则设置权限，并控制知悉范围；发生或者可能发生泄露、篡改、丢失时，应及时采取补救措施并按规定报告和通知。

**落实与验收。**

- 单独识别未成年人个人信息资产和处理活动，明确采集目的、字段、保留期限、共享对象和删除机制。
- 高敏感字段默认最小可见，批量查询、导出和跨环境复制应有审批和审计。
- 将未成年人信息访问纳入高风险行为监测，对异常批量查询、下载和跨地域访问触发告警。
- 建立面向未成年人及其监护人的查阅、更正、删除等权利响应流程。

**验收证据。**

- 随机抽一个客服、运营、研发账号，看其能否访问超出职责范围的未成年人信息？
- 未成年人注销账号后，其身份、聊天、消费和画像数据多久真正删除或匿名化？
- 测试、数据分析和AI训练是否直接使用生产未成年人数据？
- 最近一次相关数据事件是否同时评估了向监管和受影响用户/监护人通知的义务？

### 网络游戏、直播、音视频、社交等服务应提供未成年人模式

**法规要求｜第42、43条。** 网络产品和服务提供者应建立健全防沉迷制度，不得向未成年人提供诱导沉迷的产品和服务；网络游戏、网络直播、网络音视频、网络社交等服务应设置未成年人模式，并在使用时段、时长、功能和内容等方面提供相应保护，同时向监护人提供时间、权限和消费管理能力。

**落实与验收。**

- 未成年人模式应真正改变功能行为，而不是仅增加一个入口或免责声明。
- 时段、时长、夜间使用、私信、陌生人互动、直播、打赏、内容推荐等高风险功能应有明确限制。
- 监护人控制功能需要有可靠的绑定、变更和解除机制，避免未成年人自行关闭。
- 每年对外披露防沉迷工作情况前，应有内部数据和证据支撑。

**验收证据。**

- 开启未成年人模式后，逐项验证推荐内容、私信、直播、时长、夜间和付费限制是否真实生效。
- 修改系统时间、切换设备或重新注册后能否绕过时长和夜间控制？
- 监护功能是否存在默认关闭、路径过深或解除过于容易的问题？
- 年度防沉迷披露数据能否从后台原始记录复算？

### 对消费和诱导性机制设置硬限制

**法规要求｜第44、45条。** 网络游戏、直播、音视频、社交等服务应合理限制不同年龄阶段未成年人的单次和单日累计消费，不得提供与其民事行为能力不符的付费服务；同时不得诱导未成年人参与应援集资、投票打榜、刷量控评等活动。

**落实与验收。**

- 将年龄段、单笔金额、日累计、月累计和高风险商品纳入支付风控策略。
- 对打赏、礼物、榜单、抽卡、会员连续付费等设计单独评估未成年人诱导风险。
- 退款、争议处理和监护人申诉流程应能够快速定位账号、设备、订单和行为记录。
- 增长和商业化实验上线前增加未成年人保护评审，避免绕开既有支付限制。

**验收证据。**

- 未成年人账号能否通过拆单、代付、礼物转移或多个子账号绕过限额？
- 产品是否用倒计时、连续签到、榜单刺激等方式诱导未成年人持续消费？
- 监护人申请退款时，是否有可核验的年龄、设备、行为和支付证据？
- 新商业化实验是否经过未成年人保护评审？

### 防范网络欺凌并为受害未成年人提供保护

**法规要求｜相关条款。** 网络产品和服务提供者应建立健全网络欺凌行为预警预防、识别监测和处置机制，为遭受网络欺凌的未成年人及其监护人提供便捷保护措施。

**落实与验收。**

- 对侮辱辱骂、恶意曝光、围攻、人肉、持续骚扰、恶意P图等典型欺凌行为建立识别规则。
- 为未成年人提供一键屏蔽陌生人、限制评论、关闭私信、快速举报等工具。
- 重大欺凌事件进入人工快速处置通道，并避免举报后继续向受害者推荐相关内容。
- 对群组、评论区和直播间的群体性欺凌建立趋势检测和升级机制。

**验收证据。**

- 模拟多个账号持续攻击同一未成年人，系统能否识别“群体行为”而非只逐条看文本？
- 举报后涉事内容、账号和推荐链路多久停止触达受害者？
- 受害用户拉黑后，攻击者能否通过群聊、@、小号或推荐机制继续触达？
- 高风险欺凌事件是否有人工复核和升级证据？

### 投诉举报渠道必须真正可用

**法规要求｜第7条等。** 相关主体应建立便捷、合理、有效的投诉举报渠道，以显著方式公布途径和方法，并及时受理、处理和反馈。

**落实与验收。**

- 未成年人和监护人相关投诉设置独立标签、SLA和升级标准。
- 投诉入口不应隐藏在复杂层级中，关键场景允许从内容、账号、订单直接发起。
- 处置结果、复核记录和反馈证据可追溯，并能识别同类问题的重复发生。

**验收证据。**

- 从真实用户路径测试，完成一次举报需要多少步骤？
- 随机抽10个未成年人相关投诉，是否在规定SLA内处理并反馈？
- 同一账号被多人投诉时，是否会触发聚合研判，而不是每个工单独立关闭？
