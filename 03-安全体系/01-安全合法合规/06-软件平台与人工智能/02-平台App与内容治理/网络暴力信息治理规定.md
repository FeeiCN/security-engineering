# 网络暴力信息治理规定

网暴风险可能由多账号、多入口和持续传播共同形成。平台应把内容、账号、传播关系与受害者保护连起来，同时保留申诉和人工复核，避免用单一敏感词或负面评论数量直接认定网暴。本文依据[四部门令第17号正式文本](https://www.cac.gov.cn/2024-06/14/c_1720043894161555.htm)。

## 法规概览

| 项目 | 内容 |
| --- | --- |
| 公布与施行 | 2024年6月12日公布，2024年8月1日施行 |
| 适用活动 | 境内网络暴力信息治理 |
| 企业重点 | 信息服务提供者的机制、预警、信息和账号处置、用户保护及协助义务 |
| 并行规则 | 内容生态、个人信息、未成年人及具体服务专项规则 |

## 安全要求与实施

### 先建立分类和跨账号预警

**法规要求｜第7—14条。** 建立账号、个人信息保护、发布审核、监测预警等机制；依法核验相应服务用户身份；细化分类规则、特征库和案例库，综合事件、针对主体、参与人数、发布频次、场景、投诉等因素预警，并实施相应账号信用管理。

**实施建议。** 同时维护单条内容风险和针对同一对象的聚合风险。使用统一事件编号关联评论、私信、直播、群组和搜索传播，不因每条信息单独看不严重而忽略持续围攻。规则应区分合法批评、争议表达与违法或不良信息，边界案例进入人工复核。

**验收。** 用合成样本模拟多个账号围攻同一测试对象，观察聚合预警是否早于人工逐条举报；再用正常讨论样本检验误报。保存命中理由、语境、复核结果和调整记录。

### 把预警转换成传播和账号处置

**法规要求｜第13条及第四章。** 发现风险后按规定采取动态身份核验、提示、警示、限制流量等措施；出现相关浏览、搜索、评论、举报量显著增长等情形时，及时向有关部门报告。对违法信息、不良信息以及评论、群组、直播等场景，按各自条件处置并保留记录。

| 入口 | 实施建议 | 验证点 |
| --- | --- | --- |
| 评论与私信 | 内容处置联动用户防护和异常发送限制 | 原帖删除后，骚扰是否仍从私信持续到达 |
| 推荐、搜索、榜单 | 将风险状态传递到传播链路 | 已处置内容是否仍被推荐或通过镜像检索 |
| 群组与直播 | 识别组织化传播，落实管理者相应责任 | 群组、房间和关联账号是否共同进入处置 |
| 账号及组织化行为 | 识别批量操纵、营销引流等关系 | 是否仅删除单条信息而不处理持续来源 |

上述技术动作需与法规、公开平台规则及个案风险相匹配，不能把预警一律等同于永久封禁。内部可以设响应时限，但应明确其为企业控制目标，不冒充法规统一规定的分钟数。

### 给受影响用户提供真正可用的防护

**法规要求｜第五章。** 建立用户防护功能，为遭受或可能遭受侵害的用户提供相应保护；完善投诉举报、快速处置反馈和必要协助。未成年人等用户还需结合专项保护要求。

**验收示例。** 从用户正在遭到围攻的界面测试防护、评论和私信管理、举报及反馈，检查开启后是否在多端生效。攻击者换号、变体词、引用和转发后，应能继续识别关联风险；用户申诉错误限制时，应能找到受理和复核路径。

### 保存证据，避免取证造成二次传播

**法规要求｜信息处置及用户保护相关条款。** 按规定保存有关记录，依法协助用户维权及主管机关监督检查。

**实施建议。** 最小证据包包括原始内容、内容与账号标识、发布时间、传播关系、举报、判定理由、处置动作及时间、相应报告和反馈。使用受控存储、权限和导出审批；已公开过的隐私信息仍不能任意再次公开。

**验收。** 内容删除后，授权人员仍能还原处置依据；普通客服和运营无法随意下载完整隐私证据。依法提供记录时，核验请求和范围，不向投诉人直接泄露无关用户资料。

## 持续治理与完整场景

第11条要求定期发布治理公告，并将相关工作列入内容生态治理年度报告。建议从事件库统计预警、处置、申诉复核、重复侵害和防护生效情况；指标明确样本、分子分母和时间窗口，不能只展示删帖数量。

一次验收应从“多个账号集中发布涉及隐私的内容”开始，穿行预警、人工核验、止扩、用户防护、报告判断、证据保存与申诉。通过条件是各入口使用一致事实、措施与依据相匹配、处置可追溯，并能验证后续传播是否停止。
