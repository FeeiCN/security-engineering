# 中华人民共和国电子签名法

电子合同需要同时证明谁签了、同意了什么，以及签署后内容是否保持完整。图片印章、短信验证或购买签约服务，都只能构成证据的一部分。本文依据[2019年第二次修正的官方文本](https://shca.miit.gov.cn/xxgk/flfg/gjfl/art/2020/art_6c628dbd51254637b385f3d7f46aa58d.html)，技术方案为实施建议。

## 法规概览

| 项目 | 内容 |
| --- | --- |
| 首次通过与施行 | 2004年8月28日通过，2005年4月1日施行 |
| 本文依据版本 | 2019年4月23日第二次修正 |
| 主要对象 | 使用电子签名、数据电文的主体及电子认证服务提供者 |
| 核验主线 | 文书适用 → 身份与意愿 → 签名可靠性 → 文件完整性 → 长期取证 |

## 安全要求与实施

### 先确认文书能否使用电子形式

**法规要求｜第3条。** 民事活动可约定使用电子签名、数据电文，不得仅因电子形式否定效力。婚姻、收养、继承等人身关系文书，停止供水、供热、供气等公用事业服务文书，以及其他法定排除情形，不适用该条相应规定。

**验收。** 为每种合同模板记录文书类型、签约主体、适用判断及特别形式要求。现行第3条不再把不动产权益转让列为统一排除项；具体交易仍需另查登记、形式等专项要求，不能沿用旧版清单，也不能直接认为全部不动产手续都能被一次电子签替代。

### 将可靠签名的四个条件映射到实现

**法规要求｜第13—14条。** 可靠电子签名要求签名制作数据专有、签署时仅由签名人控制、签名改动可发现、签署后数据电文内容和形式改动可发现。满足要求的可靠电子签名与手写签名或盖章具有同等法律效力。

| 条件 | 实施建议 | 反向测试 |
| --- | --- | --- |
| 专有性 | 签名数据与签名人身份绑定，避免多人共享私钥 | 不同账号是否实际共用同一不受区分的签名权限 |
| 签署时控制 | 身份验证与本次文书确认关联，限制代签和后台调用 | 管理员能否不经签名人确认签署新文书 |
| 签名可检测篡改 | 使用可验证的签名算法和规范实现 | 修改签名值后独立验证是否失败 |
| 内容可检测篡改 | 签名绑定确定的文书内容和版本 | 签后修改正文、附件或关键字段是否被发现 |

使用HSM、可信时间服务等可以支持这些目标，但本法没有规定所有业务必须采用同一产品组合。服务器托管密钥也必须论证签署时的控制机制，不能把“私钥放在密码机”直接当作签名人专有控制的证明。

### 数据电文必须可调取、可解释和可复验

**法规要求｜第4—8条。** 书面形式、原件形式、保存要求和证据真实性分别有条件，应关注内容可表现和调取、完整性，以及生成、存储、传递和鉴别方法的可靠性。

建议为每笔签署保留下列证据，而非只保存带印章图片的PDF：

| 证据对象 | 要证明的问题 |
| --- | --- |
| 待签文书、附件及确定版本 | 签名人看到并认可的完整内容是什么 |
| 身份核验、意愿确认与授权记录 | 谁以什么身份和权限发起本次签署 |
| 签名值、算法及必要证书链 | 签名能否被独立验证 |
| 签署时状态与时间证据 | 签署时间、证书状态等如何核实 |
| 发送、接收、归档及访问记录 | 文件流转和保存是否可靠 |

时间戳、哈希和日志是可选技术证据，不应被表述为本法对所有电子文书统一要求的组件。哈希只能支持完整性核对，单独不能证明谁在何时表达了签署意愿。

### 证书、签名数据和认证服务边界

**法规要求｜第15—24条。** 签名人妥善保管签名制作数据，发现失密等情况及时通知并停止使用；电子签名需要第三方认证时，由依法设立的电子认证服务提供者提供。应按相关条款核验服务提供者的条件、许可与责任。

**验收。** 从实际签约服务反查电子认证服务提供者、许可、证书申请人和签署链路；签约平台与认证服务提供者可能不是同一主体。第24条针对认证服务提供者的信息保存要求，不应直接移植成所有企业所有合同的统一保存期限。企业还需结合文书、行业及争议处理要求制定自己的保存策略。

## 两类必须做的演练

**篡改演练。** 对一份测试文书分别修改正文、附件和签名，使用独立于签约页面的验证方式检查。若页面依旧显示“签署成功”，应区分流程成功与密码验证成功，修正展示和验证链路。

**失密与退出演练。** 模拟签名数据泄露或服务商退出，验证停止使用、证书状态处置、受影响签署识别、文书和证据迁出。证书今天过期不当然使过去签署失效，应保留签署时事实和验证依据，具体效力结合案件事实判断。
