# 境外安全合规

海外合规先建立实体、业务、用户、系统和数据流的事实图，再选择规则。中国侧数据出境与业务所在地的隐私、金融和网络安全要求，应分别判断并关联实施。

## 进入哪个市场

| 市场 | 当前阅读入口 | 已展开与需继续核对 |
| --- | --- | --- |
| 欧盟 | [欧盟](./01-欧盟/index.md) | 已展开GDPR、DORA；继续核对经营国、牌照及其他适用要求 |
| 新加坡 | [新加坡](./02-新加坡/index.md) | PDPA与支付监管入口；技术风险通知的现行原文仍需补核验 |
| 日本 | [日本](./03-日本/index.md) | 已展开APPI；金融和支付要求按实际业务定位 |
| 美国 | [美国](./04-美国.md) | 从联邦、经营州、数据主体和金融身份分别识别 |

页面存在只代表收录了相应主题，不代表该市场已经完成全部法规尽调。当前不新增国家和法规目录，优先把实际业务的判断与证据做完整。

## 上线前固定五组事实

| 事实 | 需要写清 |
| --- | --- |
| 法律实体与角色 | 谁签约、持牌、经营、决定数据用途或代为处理 |
| 业务与资金 | 提供什么服务，谁持有、控制或转移资金 |
| 用户与市场 | 服务对象在哪里，是否主动面向当地用户 |
| 系统与数据 | 采集、保存、访问、备份、供应商和跨境流向 |
| 事故与责任 | 哪些机构接报，谁获知、判级、报告及通知个人 |

一家公司可能有多个角色，一条数据流也可能同时满足多套规则。不能只按公司注册地、服务器位置或集团总部作出完整结论。

## 与中国数据跨境的接口

涉及境内数据被传输、查询或提供给境外主体时，进入[数据跨境](../04-数据跨境/index.md)识别适用路径。境外业务产生的数据另按当地规则判断；集团内部、远程客服、技术支持和全球分析不能默认排除。

**组合例子。** 境内系统由境外团队支持，欧盟业务又使用同一分析服务。分别判断中国出境活动、欧盟处理及第三国传输、供应商合同和权限，复用数据流事实，但不以一份合同替代两地法定程序。

## 一张跨市场义务与证据表

建议按“规则和版本 → 实体与活动 → 触发条件 → 控制 → 证据 → 报告对象与时钟 → 变化条件”维护。相同的身份、日志和供应商控制可复用，不同的合法性、报送和数据主体权利需要保留独立判断。

上线验收使用实际交易或测试账号穿行到后台、受托方和跨境访问；事件演练再核对各法域独立起算和接收方。尚未取得正式原文、适用性不明或无法验证的事项明确标记，不通过填写“已符合”消除不确定性。
