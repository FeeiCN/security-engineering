# 中国银保监会监管数据安全管理办法

本文面向监管数据处理和受托服务场景，把原办法转成采集、传输、存储、加工、使用、对外提供、委托服务、销毁和事件报告等可检查控制。该办法形成于原银保监会时期，当前使用时应结合机构改革后的监管职责和现行国家金融监督管理总局要求核对适用性。

[法规概览](#overview) · [安全要求与实施](#requirements) · [法规原文](#reference)

## 法规概览 {#overview}

| 项目 | 内容 |
| --- | --- |
| 法规 | 《中国银保监会监管数据安全管理办法（试行）》 |
| 印发时间 | 2020年9月23日 |
| 适用对象 | 原银保监会及其受托机构开展的监管数据活动 |
| 核心问题 | 监管数据采集、专网传输、存储、加工、使用、对外提供、受托服务、风险检查和重大风险报告 |
| 关键硬约束 | 重大监管数据安全风险事项应立即处置，并于48小时内向归口管理部门报告 |

## 安全要求与实施 {#requirements}

### 建立监管数据归口与业务双重责任

**法规要求｜第7—9条。** 监管数据安全实行归口管理、分工负责，归口部门负责规则、技术防护、评估检查，业务部门负责本部门数据使用和责任落实。

**落实与验收。**
- 建立监管数据目录并关联归口部门、业务责任人、系统、受托机构和处理活动。
- 重大数据处理、外部提供和技术接入明确归口审批/评估职责。
- 业务部门不能以“系统由科技维护”为由转移自身数据使用责任。

**验收证据。**
- 随机指定一份监管报表，谁负责业务正确性、谁负责安全、谁批准对外使用？
- 从一次违规使用或安全事件反查，责任能否落到具体业务和技术岗位？

### 控制采集、传输、存储和技术接入

**法规要求｜第10—15条。** 数据采集应避免重复和过度；原则上通过监管工作网或金融专网传输、存储于规定机房；例外路径和受托存储需评估同意；代码、接口、算法模型和开发工具接入监管系统需批准。

**落实与验收。**
- 采集字段与监管目的逐项对应，定期清理重复、失效字段。
- 专网为默认传输路径，互联网、介质、VPN等例外建立事前评估和加密、审计控制。
- 存储位置、备份和副本进入统一资产清单，受托机构不得自行扩散副本。
- 外部代码、模型、接口和工具接入实施白名单、评估、版本和权限管理。

**验收证据。**
- 从实际网络流量反查监管数据是否存在未经批准的互联网传输？
- 从受托机构存储反查审批，是否存在测试、备份或临时文件形成未登记副本？
- 扫描监管系统外联和插件，是否有未经评估的模型、接口或开发工具？

### 将监管数据使用限制在职责和授权范围

**法规要求｜第16—23条。** 监管数据原则上限于履行监管职责使用，行为应可追溯；开发测试和对外展示应脱敏；未公开数据原则上在不连接互联网的工作机使用，下载和对外提供受到严格控制。

**落实与验收。**
- 访问授权基于监管职责和最小必要，所有查询、下载和导出关联具体人员。
- 未公开数据与互联网环境隔离；例外远程使用必须经过评估和受控接入。
- 开发测试、展示和分析环境使用脱敏数据，加工结果继续按监管数据管理。
- 对外提供明确审批、接收方、字段、用途、保密和后续处置要求。

**验收证据。**
- 随机抽一个监管数据用户，实际权限是否超出工作职责？
- 从终端/DLP记录反查，是否有监管数据进入个人电脑、互联网云盘或普通协作工具？
- 从对外提供记录反查实际文件，字段是否超出批准范围？

### 对受托机构实施准入、变更、持续监督和退出闭环

**法规要求｜第24—27条。** 委托服务应事先沟通会签并通过安全评估；受托机构应具备相应安全、研发运维、备份应急能力；技术方案变更需重新评估；关系终止时完整移交并销毁数据和备份。

**落实与验收。**
- 受托机构准入验证技术、安全、机房、连续性和历史事件情况。
- 合同明确数据范围、访问、事件通知、分包、审计、移交和销毁责任。
- 架构、数据中心、分包和技术方案变化自动触发重新评估。
- 退出时执行账号回收、数据移交、介质/备份销毁和独立验证。

**验收证据。**
- 抽一个在用受托机构，当前技术方案与最近一次安全评估是否一致？
- 抽一个已退出供应商，能否证明所有生产、测试和备份数据都已销毁？
- 如果供应商今天发生重大故障，监管数据和服务能否恢复？

### 建立48小时重大风险报告与整改闭环

**法规要求｜第28—31条。** 应定期自查和评估；发生数据泄露、非法使用、损毁丢失、系统性故障中断4小时以上、非法入侵、大规模恶意传播、舆情等重大风险事项时立即处置，并于48小时内报告归口部门。

**落实与验收。**
- 将重大风险条件固化到事件分级规则，并从首次发现/获知时间计时。
- 报告和应急处置并行，不等待完整根因才启动报告。
- 自查、评估和事件发现统一进入问题整改库并复测关闭。

**验收证据。**
- 从历史P1/P2事故和数据事件反查，是否存在符合条件却未进入48小时报告流程的事项？
- 模拟周末发现监管数据泄露，谁报告、向谁报、如何保证48小时内完成？
- 已整改问题是否通过生产复测，而不是只提交整改说明？
