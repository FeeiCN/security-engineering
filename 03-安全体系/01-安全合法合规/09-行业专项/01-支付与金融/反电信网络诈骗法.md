# 中华人民共和国反电信网络诈骗法

本文从银行、支付机构和互联网服务提供者视角，把反诈义务转成新业务评估、实名与账户治理、异常交易监测、涉诈互联网资源治理、风险处置和跨机构协同等可执行控制。检查重点不是“部署了反诈系统”，而是从真实涉诈样本反查，风险是否被识别、措施是否与风险匹配、信息用途是否越界、处置是否可申诉和恢复。

[法规概览](#overview) · [安全要求与实施](#requirements) · [法规原文](#reference)

## 法规概览 {#overview}

| 项目 | 内容 |
| --- | --- |
| 法规 | 《中华人民共和国反电信网络诈骗法》 |
| 生效日期 | 2022年12月1日 |
| 重点义务主体 | 电信业务经营者、银行业金融机构、非银行支付机构、互联网服务提供者 |
| 核心问题 | 实名、账户与支付治理、异常监测、新业务涉诈评估、互联网资源治理、技术阻断、协同止付冻结、用户救济 |

下文按 **“法规要求 → 落实与验收”** 展开：每项要求同时说明实施动作与可验证证据。不同主体只适用与其身份相关的义务；金融机构还应叠加反洗钱、支付监管等规则。

## 安全要求与实施 {#requirements}

### 把涉诈风险评估前置到新业务和重大变更

**法规要求｜第6条等。** 电信业务经营者、银行业金融机构、非银行支付机构、互联网服务提供者承担风险防控责任，应建立内部控制和安全责任制度，加强新业务涉诈风险安全评估。

**落实与验收。**
- 新产品、新支付链路、新账户能力、新营销/社交功能和重大规则变更上线前完成涉诈风险评估。
- 评估覆盖身份冒用、批量注册、账户买卖、异常资金流、钓鱼引流、黑灰产自动化和处置绕过。
- 高风险问题形成上线门禁、补偿控制和责任人；上线后用真实欺诈数据复核评估假设。

**验收证据。**
- 从最近半年上线的高风险功能随机抽样，能否找到上线前涉诈评估和实际控制？
- 给出“新增免密/快速转账/批量开户入口”等场景，团队会在哪个环节阻断上线？
- 对上线后出现重大涉诈损失的功能，原评估是否遗漏了已知攻击路径，是否完成复盘和规则更新？

### 做实客户身份、账户和支付账户治理

**法规要求｜第15—17、21条等。** 金融和支付机构应开展客户尽职调查、识别受益所有人并防范账户被用于诈骗；互联网相关特定服务应依法落实真实身份信息要求。

**落实与验收。**
- 开户、注册、关键账户变更和高风险操作建立真实身份核验和异常识别。
- 企业账户结合主体登记、受益所有人、设备、联系方式和关联账户识别异常开户。
- 对批量注册、冒用身份、异常持有数量和账户买卖风险建立差异化核验与限制措施。
- 风险解除后具备复核和恢复路径，避免永久性“一刀切”。

**验收证据。**
- 从已确认涉诈账户反查开户阶段，哪些风险信号当时已经存在但未被识别？
- 模拟同设备、同联系方式或异常主体批量开户，系统是否触发加强核验？
- 随机抽一个受限制但后续申诉成功的用户，限制、复核和恢复时间线是否完整？

### 建立异常账户和可疑交易实时监测与分级处置

**法规要求｜第18—20条。** 银行和支付机构应建立异常账户、可疑交易监测机制，并可根据风险采取核实交易、重新核验身份、延迟支付、限制或中止业务等措施；应配合涉案资金即时查询、紧急止付、快速冻结、解冻和返还。

**落实与验收。**
- 风险模型覆盖账户、设备、IP、交易对手、资金路径、行为速度和历史风险等维度。
- 处置动作与风险等级对应，明确自动/人工决策、时限、升级和解除条件。
- 公安止付冻结指令进入高可用链路，主备人员和非工作时间均可执行。
- 反诈目的收集的设备/IP等信息实施目的限制，不得未经授权转作营销画像等用途。

**验收证据。**
- 从已确认诈骗资金链反查，第一笔异常交易出现到首次风控动作间隔多久？
- 随机抽一个延迟支付/限制账户案例，风险证据是否足以支撑所采取措施？
- 模拟夜间紧急止付，系统和人员能否在要求窗口内完成？
- 从数据平台反查反诈专用字段，是否被其他营销或推荐任务直接调用？

### 治理涉诈互联网账号、域名、App和技术资源

**法规要求｜第14、21条及互联网治理相关条款。** 对特定互联网服务落实实名要求；互联网服务提供者应识别、阻断用于诈骗的非法设备、软件和相关网络资源，并依法采取处置和报告措施。

**落实与验收。**
- 建立涉诈账号、域名、URL、App、设备、IP和内容线索的统一风险实体库。
- 注册、登录、内容发布、链接传播、支付跳转等关键链路共享风险信号。
- 对批量账号、验证码接码、异常代理、钓鱼链接等黑灰产能力建立检测和阻断。
- 外部举报、公安/监管通报进入同一处置链路，并保留原始线索和结果。

**验收证据。**
- 从一条已确认钓鱼链接反查传播账号、关联设备和支付落点，是否能形成关联处置而不是只删URL？
- 模拟批量注册+代理IP+接码平台组合，是否能绕过单点规则？
- 从公安通报样本反查内部检测，为什么外部先发现，缺失的是数据、规则还是处置？

### 保证交易信息真实、完整和全链路一致

**法规要求｜第19条。** 银行和支付机构应完整、准确传输直接提供商品或服务的商户名称、收付款客户名称及账号等交易信息，保证交易信息真实、完整和支付全流程一致。

**落实与验收。**
- 商户、收付款方和交易标识在受理、路由、清算、账务和风控链路保持一致。
- 禁止中间系统为了兼容、聚合或展示便利丢失真实商户和交易主体信息。
- 对字段转换、聚合支付和跨机构接口建立数据质量监控和异常告警。

**验收证据。**
- 随机抽一笔真实支付，从用户端一直穿行到清算/账务，商户和收付款主体是否一致？
- 找一笔聚合支付交易，最终风控看到的是实际商户还是只有聚合服务商？
- 从涉诈交易反查，是否因字段缺失导致资金链无法准确关联？

### 建立精准处置、申诉救济和跨机构协同

**法规要求｜第5、7条及相关处置条款。** 反诈工作应依法精准防治并保障正常生产经营和群众生活便利；有关部门和单位应协同联动，并保护工作中知悉的个人信息等。

**落实与验收。**
- 所有限制措施明确依据、风险等级、持续时间、解除条件和申诉渠道。
- 对误伤率、申诉成功率、恢复时长进行持续监测，反向优化规则。
- 跨机构共享坚持反诈目的、最小必要、权限控制和可审计。
- 重大涉诈事件形成复盘，覆盖攻击链、资金链、账户链和控制失效点。

**验收证据。**
- 随机抽取误伤申诉案例，用户从提交到恢复用了多久，是否存在无人负责的状态？
- 某风险规则命中率很高但误伤也高时，谁有权调整，依据什么数据？
- 抽取一次跨机构风险信息共享，能否证明共享目的、字段范围、接收方和后续使用受控？
