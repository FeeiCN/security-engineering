# 汽车数据安全管理若干规定（试行）

本文把汽车制造、零部件/软件、经销维修和出行服务中的数据要求转成车内优先、默认不收集、个人信息、重要数据、数据出境和年度报告等可验证控制。检查重点应落到真实车辆、真实固件、真实App和真实后端数据流，而不是只检查隐私政策。

[法规概览](#overview) · [安全要求与实施](#requirements) · [法规原文](#reference)

## 法规概览 {#overview}

| 项目 | 内容 |
| --- | --- |
| 法规 | 《汽车数据安全管理若干规定（试行）》 |
| 生效日期 | 2021年10月1日 |
| 主要主体 | 汽车制造商、零部件和软件供应商、经销商、维修机构、出行服务企业等汽车数据处理者 |
| 核心问题 | 车内处理、默认不收集、最小精度、个人信息、敏感个人信息、重要数据、境内存储、出境评估、年度报告 |
| 关键时限 | 敏感个人信息删除请求原则上10个工作日；重要数据处理者每年12月15日前报送年度汽车数据安全管理情况 |

## 安全要求与实施 {#requirements}

### 把车内处理、默认不收集和最小精度落实到产品默认值

**法规要求｜第4—6条。** 汽车数据处理应合法、正当、具体明确并与汽车业务直接相关；倡导车内处理、默认不收集、精度范围适用和脱敏处理。

**落实与验收。**
- 对摄像头、麦克风、位置、驾驶行为、车外图像等逐项判断是否可在车端完成计算。
- 新车/恢复出厂后的默认状态不主动开启非必要采集，用户主动选择后才改变。
- 传感器覆盖范围、分辨率和上传精度按功能最小化，避免“硬件能采多少就采多少”。
- 能匿名化、特征化或仅上传结果的，不默认上传原始音视频和轨迹。

**验收证据。**
- 将车辆恢复出厂设置，在用户不做任何授权的情况下抓取车端到云端流量，实际上传了什么？
- 关闭云端网络后，声称必须上传的数据是否其实仍能在车内实现功能？
- 检查摄像头原始分辨率与业务实际使用精度，是否存在明显过度采集？

### 让告知、同意和停止采集能力作用于真实车端

**法规要求｜第7—9条。** 处理个人信息应显著告知；敏感个人信息需满足更严格必要性、单独同意、状态提示和停止采集要求，删除请求原则上10个工作日内完成。

**落实与验收。**
- 用户手册、车机和App中的处理规则与真实传感器、SDK和云端处理一致。
- 敏感信息单独同意按具体目的和数据类型设计，不捆绑在总隐私协议中。
- 车机明确展示敏感数据采集状态，并提供易用的停止方式。
- 删除请求贯穿车端缓存、云端、备份和受托方，并跟踪到完成。

**验收证据。**
- 用户拒绝人脸/声纹/轨迹等敏感信息后，相关传感器和上传链路是否真的停止？
- 提交一次删除请求，10个工作日后从主库、缓存和第三方链路反查是否仍可找到数据？
- 对照隐私告知抓真实网络流量，是否存在未告知字段或用途？

### 识别重要数据并在处理前完成风险评估

**法规要求｜第3、10条。** 重要数据包括特定敏感区域地理/流量、经济运行相关车辆物流数据、充电网运行数据、含人脸/车牌的车外图像，以及涉及超过10万个人信息主体的数据等；开展重要数据处理活动应进行风险评估并按规定报送。

**落实与验收。**
- 建立汽车重要数据识别规则和目录，覆盖单车数据聚合后达到规模/敏感程度的情况。
- 重要数据处理项目在上线和重大变化前完成风险评估，记录种类、规模、范围、存储、第三方提供、风险和措施。
- 车外视频/图像、人流车流等数据重点评估聚合和区域属性，不能只按单张图片判断。

**验收证据。**
- 从云端车外图像库反查，是否包含人脸、车牌或敏感区域数据却未识别为重要数据？
- 当前个人信息主体规模是否已超过10万，达到阈值后何时触发重新分类和评估？
- 抽一项重要数据业务，风险评估时间是否早于实际处理？

### 对重要数据实施境内存储和严格出境控制

**法规要求｜第11—12条。** 重要数据应依法境内存储，确需向境外提供的应通过安全评估，实际出境不得超出评估明确的目的、范围、方式、种类和规模。

**落实与验收。**
- 建立车辆、云平台、研发工具、境外远程支持和SaaS的完整数据出境地图。
- 重要数据默认境内存储；远程查询、日志平台、模型训练和境外技术支持同样纳入出境识别。
- 出境批准参数与网络/API实际传输建立持续对账，超范围自动告警或阻断。

**验收证据。**
- 从境外IP流量和跨国账号反查，是否存在未登记的远程访问或日志同步？
- 随机抽一条获批出境链路，实际字段、规模和接收方是否与评估完全一致？
- 境外研发人员能否通过内部工具间接查询重要数据？

### 建立年度报告、投诉和事件事实闭环

**法规要求｜第13—17条。** 重要数据处理者应在每年12月15日前报送年度汽车数据安全管理情况；出境重要数据还需补充相关情况；应建立投诉举报渠道并配合安全评估。

**落实与验收。**
- 年度报告数据从资产、处理活动、第三方共享、事件和投诉系统自动汇总，避免年底临时统计。
- 报告中的种类、规模、存储地点、第三方和出境情况与生产事实一致。
- 用户投诉进入隐私/数据治理闭环，高频问题推动产品整改。
- 重大数据事件与网络安全事件统一研判并履行相应报告义务。

**验收证据。**
- 将上一年度报告中的数据规模和第三方清单与当前历史日志复算，是否一致？
- 随机抽一条用户投诉，是否能看到从受理到技术整改和反馈的完整记录？
- 年中新增重要数据业务后，年度报告数据源是否自动覆盖，还是依赖负责人记得补填？
