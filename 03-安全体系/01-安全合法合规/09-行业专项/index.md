# 行业专项

先完成通用网络、数据和个人信息判断，再确认本行业是否增加了特定对象、处理限制、评估或报告要求。行业身份不应成为重复建设整套安全流程的理由。

## 按实际场景选择

| 当前业务 | 优先阅读 | 重点问题 |
| --- | --- | --- |
| 汽车制造、零部件软件、经销维修或出行数据 | [汽车数据安全管理若干规定](./02-汽车/汽车数据安全管理若干规定.md) | 车端处理、敏感信息、重要数据及年度报告 |
| 银行、支付或其他金融业务 | [支付与金融安全](./01-支付与金融/index.md) | 牌照主体、行业数据和事件规则 |
| 政务网站、办公系统、政务云或信息共享 | [政务与办公](./03-政务与办公/index.md) | 具体系统、数据流和专项技术要求 |
| App、内容、算法或AI服务 | [平台App与AI](../06-软件平台与人工智能/index.md) | 产品能力、用户群和专项程序 |
| 境外经营或海外客户服务 | [海外业务安全合规](../10-境外安全合规/index.md) | 当地准入、数据、系统与报告 |

支付金融、汽车和政务办公分别设置主题入口；医疗健康、快递物流和电信领域的现有标准列在本页。未列出的行业不代表没有专项规则，实际进入业务前仍需核对主管机关和产品形态。

## 汽车场景的组合阅读

车机采集位置、影像或人脸时，先核对汽车数据专项条件，再衔接[个人信息保护](../03-数据安全与个人信息/index.md)；境外研发查询、日志同步和云服务涉及跨境时，继续进入[数据跨境](../04-数据跨境/index.md)。车端、App、后台和受托方应在同一张数据流图中。

## 验收结果应具体到业务对象

建议为每项专项义务记录车型或服务、数据对象、控制位置、责任方和证据。以车辆或真实接口验证默认设置、采集状态、传输、删除及报告材料，而不只核对隐私政策。

行业专项文件随行业场景归档，通用数据、密码和网络安全文件通过链接复用。平台服务和境外监管继续通过各自主题查找。
