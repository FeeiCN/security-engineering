# 人员与专业机构资质

这里必须先区分两件事：

> **个人证书证明人的能力；机构资格证明组织能否开展特定专业评估。**

个人有CISSP、CISP或OSCP，不意味着其所在公司自动具备等保、密评或PCI第三方评估资格。

## 个人职业认证

| 方向 | 常见认证 | 更适合的岗位/场景 | 不能替代 |
| --- | --- | --- | --- |
| 综合安全 | CISSP、CISP | 安全架构、安全负责人、综合安全岗位 | 企业/系统法定测评 |
| 安全治理 | CISM | 安全管理、治理、风险负责人 | 法定机构资质 |
| IT审计 | CISA | IT审计、控制评价、风险 | SOC/监管要求的独立机构 |
| 云安全 | CCSP | 云安全架构、云治理 | 云服务自身的认证/授权 |
| 攻防 | OSCP / OSCE³ | 渗透测试、红队 | 法定测评机构资格 |
| 专项技术 | GIAC系列 | 取证、应急、攻防等细分方向 | 具体监管资质 |
| PCI内部 | PCI ISA | 企业内部PCI能力 | QSA Company第三方评估资格 |

选择个人证书时先看岗位能力模型，而不是证书知名度。对CISO/安全管理岗位，治理、架构、风险和审计类能力通常比单纯堆叠技术证书更重要；攻防岗位则相反。

## 专业评估机构与人员体系

| 体系 | 机构/人员 | 主要作用 |
| --- | --- | --- |
| 等级保护 | 等保测评机构及相关测评人员能力 | 开展等级保护测评 |
| 商用密码 | 密评机构、相关从业人员 | 开展商用密码应用安全性评估 |
| PCI DSS | QSA Company / QSA | 第三方PCI DSS评估 |
| PCI内部 | ISA | 提升组织内部PCI评估和准备能力 |
| PCI P2PE | P2PE Assessor等 | 对P2PE方案开展相应评估 |

实际开展受监管或行业规则约束的第三方评估时，应核对**机构是否在有效名录/官方listing中、具体人员状态是否有效、业务范围是否覆盖当前项目**。

## 怎么选个人证书

```text
先定岗位
  ├─ CISO / 安全治理 → CISSP / CISM / CISA / CISP
  ├─ 云安全 → CCSP + 云厂商专项能力
  ├─ 红队 / 渗透 → OSCP / OSCE³ / GIAC专项
  ├─ IT审计 → CISA
  └─ PCI专业岗位 → ISA / QSA等按角色判断
```

证书只是能力证据的一部分。招聘或晋升时更应该同时验证真实项目、复杂问题处理、架构判断、沟通治理和持续实践。

## 企业采购专业机构时验什么

- 机构是否在主管方或规则机构的有效名录/listing；
- 资质范围是否覆盖当前业务；
- 实际项目人员是否具备要求的有效资格；
- 是否存在独立性或利益冲突要求；
- 报告最终由谁签发、谁承担责任；
- 机构或人员状态变化后是否影响报告有效性。

## 不要混淆

- **培训结业证 ≠ 职业认证；**
- **个人职业认证 ≠ 法定机构资质；**
- **机构有资质 ≠ 任意员工都能签署评估；**
- **证书仍在手 ≠ 当前状态一定有效。**

## 官方核验与持续有效性

人员和机构资格通常具有状态变化，应优先通过**发证组织、主管机构或规则机构的官方名录/验证渠道**核验，而不是只留一份历史证书扫描件。

采购专业评估服务时，把“机构状态 + 项目人员状态 + 业务范围 + 核验日期”一起记录。人员离职、证书失效、机构资格变化后重新判断。
