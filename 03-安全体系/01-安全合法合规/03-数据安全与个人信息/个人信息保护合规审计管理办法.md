# 个人信息保护合规审计管理办法

本文用于把个人信息合规审计从“定期做一次审计”转成可持续的审计范围、证据、整改和复测机制。

[法规概览](#overview) · [安全要求与实施](#requirements) · [法规原文](#reference)

## 法规概览 {#overview}

| 项目 | 内容 |
| --- | --- |
| 法规 | 《个人信息保护合规审计管理办法》，国家互联网信息办公室令第18号 |
| 生效日期 | 2025年5月1日 |
| 主要适用对象 | 在境内开展个人信息保护合规审计的个人信息处理者及受托专业机构 |
| 关键阈值 | 处理超过1000万人个人信息的处理者，每两年至少审计一次；监管要求开展审计时适用专门程序 |
| 官方来源 | [国家互联网信息办公室](https://www.cac.gov.cn/2025-02/14/c_1741233507681519.htm) |

下文按 **“法规要求 → 落实与验收”** 展开：每项要求同时说明实施动作与可验证证据。附件《个人信息保护合规审计指引》本身就是重要检查依据，企业不应只做制度符合性审查。

## 安全要求与实施 {#requirements}

| 核心主题 | 达成状态 |
| --- | --- |
| 审计触发与频次 | 知道什么时候必须审、由谁审、适用什么频次 |
| 审计范围与方法 | 能覆盖真实个人信息处理活动，而不是只审政策文本 |
| 专业机构与独立性 | 外部审计机构资质、独立性和保密义务受控 |
| 报告与整改 | 审计结论、监管报送、整改和复测形成闭环 |
| 负责人和监督机制 | 大规模处理者的负责人和独立监督要求真实运行 |

### 正确识别审计触发条件和频次

**法规要求｜第3—6条。** 个人信息处理者应定期开展合规审计；处理超过1000万人个人信息的，每两年至少开展一次。存在较大风险、可能侵害众多个人权益，或发生达到规定规模的个人信息安全事件时，保护部门可以要求委托专业机构开展审计。

**落实与验收。**

- 维护个人信息处理规模、敏感信息规模和重大事件数据，能够判断是否命中法定审计触发条件。
- 建立年度审计计划和触发式专项审计机制，不把“两年至少一次”理解为所有机构统一频次。
- 收到监管要求后，单独管理专业机构选择、限定完成时间、报告报送和整改要求。
- 同一事件或风险是否存在重复审计要求时，按办法规定和监管要求核实处理。

**验收证据。**

- 当前处理个人信息规模是多少，统计口径从哪里来，能否从系统数据复算？
- 最近一次达到1000万人阈值是什么时候，下一次法定审计最迟何时完成？
- 给出“100万人个人信息泄露”或“10万人敏感个人信息泄露”的场景，团队是否知道可能触发监管要求的专业审计？
- 审计计划是否随着规模、业务和事件变化动态调整，而不是固定日历任务？

### 按审计指引覆盖真实处理活动

**法规要求｜第6条及附件。** 自行或监管要求开展合规审计时，应参照《个人信息保护合规审计指引》审查个人信息处理活动是否合法合规。

**落实与验收。**

- 将合法基础、告知同意、委托/共享、自动化决策、敏感信息、未成年人、跨境、删除与行权、内部制度、安全技术措施、培训、影响评估和事件响应等纳入审计范围。
- 审计样本从真实业务、系统、SDK、接口、权限、日志和用户请求中抽取，不只依赖隐私制度和自评问卷。
- 对关键技术控制验证“是否有效”，必要时现场测试、重新计算或从原始日志反查。
- 对不适用项记录事实和依据，不用“N/A”隐藏证据不足。

**验收证据。**

- 从生产系统反查审计范围，是否有业务或数据处理活动完全没被抽到？
- 抽一项“审计结论为通过”的控制，能否从原始系统和日志独立复现？
- 审计是否测试过用户权利、撤回同意、删除、第三方退出等真实流程？
- 报告里大量使用“已建立、已具备”时，是否对应具体样本和证据？

### 管理专业机构的能力、独立性和保密

**法规要求｜第7—15条。** 专业机构应具备相应能力，依法保密，不得转委托；同一专业机构及其关联机构、同一审计负责人不得连续三次以上对同一审计对象开展审计。

**落实与验收。**

- 采购前核实专业机构人员、方法、场所、设施和审计能力，并识别关联关系和历史连续服务次数。
- 合同明确独立性、保密、数据最小化、审计结束后的信息删除和禁止转委托要求。
- 审计期间对专业机构访问生产数据、敏感信息和日志采用最小权限及留痕控制。

**验收证据。**

- 当前审计机构连续服务了几次，关联机构是否被错误当作新的独立机构？
- 审计数据结束后如何证明已删除，是否仍留在审计方网盘或个人终端？
- 外部机构是否把核心工作转给了未披露的第三方？
- 审计团队访问了哪些生产数据，权限是否在项目结束后及时回收？

### 形成报告、整改和复测闭环

**法规要求｜第9—11条。** 按保护部门要求开展审计时，应在限定时间完成并报送由专业机构相关负责人签字、盖章的审计报告；按照要求整改，整改完成后15个工作日内报送整改情况报告。

**落实与验收。**

- 建立审计发现项台账，记录事实、法规依据、风险、责任人、整改期限和复测方法。
- 监管要求审计时，单独管理法定/监管时限、报告签字盖章、正式报送和收悉证据。
- 整改完成后针对原失败条件复测，不以责任人自述“已完成”关闭问题。
- 整改情况报告与实际复测结果一致，历史问题不通过补材料改写成“原本已合规”。

**验收证据。**

- 最近一次审计发现的问题是否每一项都有整改和复测结果？
- 被监管要求审计时，报告是否在限定时间正式报送，而不是只在内部完成？
- 整改完成后15个工作日内的整改情况报告是否按要求提交？
- 随机抽一个“已关闭”问题，现场重做原测试是否仍能通过？

### 落实个人信息保护负责人和独立监督要求

**法规要求｜第12条。** 处理100万人以上个人信息的处理者应指定个人信息保护负责人负责合规审计工作；提供重要互联网平台服务、用户数量巨大、业务类型复杂的处理者还承担独立监督机构相关要求。

**落实与验收。**

- 按处理规模识别负责人义务，明确其审计规划、协调、整改推动和向管理层报告职责。
- 负责人具备获取审计证据和推动跨部门整改的实际权限，不只是名义任命。
- 适用独立监督机构要求的主体，建立成员、职责、议事、监督和跟踪机制。

**验收证据。**

- 当前处理规模是否已经达到100万人，负责人是否已经正式指定并实际主持审计工作？
- 负责人能否推动业务整改，还是只能提出建议没有闭环权限？
- 适用独立监督要求时，外部成员是否真正参与审计监督和问题跟踪？
- 最近一次重大审计问题是否进入管理层或独立监督机制讨论？
