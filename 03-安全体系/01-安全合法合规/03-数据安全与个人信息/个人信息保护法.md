# 中华人民共和国个人信息保护法

本文用于把《个人信息保护法》从“知道法条”转成“知道业务里要做什么、做到什么状态、如何验证”。

[法规概览](#overview) · [安全要求与实施](#requirements) · [法规原文](#reference)

## 法规概览 {#overview}

| 项目 | 内容 |
| --- | --- |
| 法规 | 《中华人民共和国个人信息保护法》 |
| 生效日期 | 2021年11月1日 |
| 主要适用对象 | 决定个人信息处理目的、方式的个人信息处理者；符合第3条规定的部分境外处理活动同样适用 |
| 核心问题 | 处理个人信息有没有合法基础、是否最小必要、敏感信息是否加强保护、个人权利能否实现、共享委托和出境是否受控、安全责任是否真正落实 |
| 官方来源 | [中国人大网](https://www.npc.gov.cn/npc/c2/c30834/202108/t20210820_313088.html) |

下文按 **“法规要求 → 落实与验收”** 展开：每项要求同时说明实施动作与可验证的验收标准。法条要求与实施建议分开表述；实施方式可以因机构而异，但不能降低法定义务。

## 安全要求与实施 {#requirements}

| 核心主题 | 达成状态 |
| --- | --- |
| 处理清单与合法基础 | 每项个人信息处理活动都知道处理什么、为什么处理、凭什么处理 |
| 告知同意与最小必要 | 告知真实完整，需要同意时能有效取得、撤回和重新取得，不超范围收集 |
| 敏感信息与未成年人 | 高风险信息有更严格必要性、同意和保护措施 |
| 共享委托与自动化决策 | 数据流向、第三方责任和算法使用边界清楚且可持续监督 |
| 个人权利 | 查阅、复制、更正、删除、撤回同意等请求可实际完成 |
| 跨境提供 | 出境场景、路径、评估、合同/认证/安全评估等要求被正确识别 |
| 安全治理与事件 | 责任、权限、培训、影响评估、应急和事件通知形成闭环 |

### 建立个人信息处理清单和合法基础

**法规要求｜第4—13条。** 个人信息处理应遵循合法、正当、必要、诚信、公开透明等原则，并具有第13条规定的合法处理基础。

**落实与验收。**

- 建立覆盖收集、存储、使用、加工、传输、提供、公开、删除等环节的个人信息处理活动清单。
- 对每项活动记录处理目的、信息种类、数据主体、来源、使用方、保存期限、系统和处理依据。
- 不把“用户注册过”“业务一直这么做”“写进隐私政策”当作合法处理基础；需要同意的场景与依法无需同意的场景分别管理。
- 业务目的、处理方式或信息种类变化时触发重新评估，避免一次审批永久有效。

**验收标准。**

- 从真实系统、数据库字段、SDK、埋点和数据接口反查处理清单，能否发现未登记的数据处理活动？
- 随机抽一项处理活动：团队能否说清具体处理目的、合法基础、保存期限和使用方，而不是只回答“用户同意了”？
- 最近一次业务功能变化后，处理清单和合法基础是否同步更新？
- 对依法无需同意的处理活动，能否拿出相应适用依据；对依赖同意的活动，是否存在有效同意记录？

### 做到告知、同意和最小必要

**法规要求｜第14—19条。** 基于同意处理个人信息时，同意应在充分知情前提下自愿、明确作出；个人可撤回同意。处理前应依法告知，保存期限原则上应为实现目的所必要的最短时间。

**落实与验收。**

- 隐私告知覆盖处理者信息、目的、方式、信息种类、保存期限和个人行权方式，并保持与真实处理活动一致。
- 单独同意、书面同意、重新同意等特殊要求按适用场景单独实现，不用一揽子同意替代。
- 撤回同意应当真实可用，并联动停止相应处理；不能设置明显高于授权时的操作成本。
- 把“最小必要”落实到字段、权限、SDK、接口和保存期限，不只停留在政策文本。

**验收标准。**

- 对照真实数据字段和第三方SDK逐项检查隐私告知，是否存在“实际收了但没写”“写了但实际不用”的差异？
- 现场走一遍同意与撤回流程：拒绝非必要信息后基本功能是否仍可使用，撤回后后台是否真的停止相应处理？
- 随机抽一个长期保存字段：为什么需要保存这么久，谁批准，期限到后如何删除或匿名化？
- 功能目的变化后是否重新取得适用的同意，还是沿用旧授权？

### 加强敏感个人信息和未成年人信息保护

**法规要求｜第28—32条。** 处理敏感个人信息须具有特定目的和充分必要性并采取严格保护措施；基于同意时原则上取得单独同意。处理不满十四周岁未成年人个人信息时适用专门要求。

**落实与验收。**

- 建立敏感个人信息清单和识别规则，覆盖生物识别、医疗健康、金融账户、行踪轨迹等以及不满十四周岁未成年人个人信息。
- 在产品设计阶段说明处理敏感信息的必要性、对个人权益的影响和保护措施，并完成适用的单独同意或其他合法基础判断。
- 对敏感信息实行更严格的访问控制、加密、脱敏、导出和日志审计措施。
- 涉及不满十四周岁未成年人时建立监护人同意和专门处理规则。

**验收标准。**

- 从数据资产中反查敏感个人信息，是否存在因字段名称不明显而漏标的金融、轨迹、生物识别信息？
- 随机抽一项敏感信息处理：为什么“充分必要”，对应的单独同意或其他处理依据在哪里？
- 现场查看敏感数据的查询、导出和特权账号控制，普通人员是否能绕过流程直接获得明文？
- 对未成年人场景，如何判断年龄、如何取得监护人同意，专门规则是否真实生效？

### 管住委托、共同处理、对外提供和自动化决策

**法规要求｜第20—27条、第55条。** 共同处理、委托处理、向其他处理者提供、公开个人信息以及自动化决策等场景分别有责任约定、告知同意、影响评估和用户权益要求。

**落实与验收。**

- 建立个人信息接收方、受托方和共享场景清单，合同约定处理目的、期限、方式、信息种类、保护措施和退出要求。
- 对受托方实施持续监督，合同终止时验证返还或删除；转委托按要求受控。
- 对外提供、公开和高风险自动化决策在上线或重大变更前完成个人信息保护影响评估。
- 自动化决策提供透明度、拒绝/退出和必要的人工解释或干预机制，不以算法系统为由拒绝个人依法行权。

**验收标准。**

- 从网络流量、数据接口、采购合同和SDK反查第三方清单，能否发现清单外接收方？
- 随机抽一个受托方：合同约定与实际获得的数据、用途、保存期限是否一致，最近一次监督是什么时候？
- 合同终止后，能否证明数据已返还或删除，而不是只有供应商口头确认？
- 抽一个自动化决策场景，用户能否获得解释、拒绝仅由自动化方式作出的重大影响决定，并能否实际停止个性化推送或营销？

### 保障个人权利能够真正执行

**法规要求｜第44—50条。** 个人依法享有知情、决定、限制或拒绝处理、查阅复制、转移、更正补充、删除等权利，处理者应建立便捷受理和处理机制。

**落实与验收。**

- 建立统一个人权利请求入口，覆盖不同产品、渠道和数据系统。
- 把身份核验、数据检索、审批、执行、答复和异常升级形成端到端流程。
- 数据分散在主库、日志、备份、第三方或离线平台时，明确哪些需要执行、如何执行、哪些依法不能立即删除及其处理方式。
- 对拒绝请求形成具体理由和复核机制。

**验收标准。**

- 用一个真实测试账号发起查阅、复制、更正和删除请求，后台能否在各系统中找到并一致执行？
- 用户注销后，哪些数据仍保留，为什么保留，是否停止了非必要处理？
- 最近几起被拒绝的行权请求，理由是否有法律依据，还是以“系统暂不支持”作为长期理由？
- 从客服投诉反查权利请求台账，是否存在用户已经提出要求但未被识别为行权请求的情况？

### 管理个人信息跨境提供

**法规要求｜第38—43条。** 向境外提供个人信息，应满足法定出境条件并依法履行告知、单独同意、影响评估等义务；达到相应条件时适用安全评估、认证、标准合同等路径。

**落实与验收。**

- 建立个人信息出境数据流地图，识别境外接收方、传输方式、远程访问、云服务和集团内部共享等场景。
- 按最新跨境规则判断是否豁免、是否需要安全评估、认证或标准合同，避免只按合同签署地点判断是否“出境”。
- 出境前完成适用的告知、单独同意和个人信息保护影响评估，并持续监督境外接收方履约。
- 出境目的、范围、接收方、保存地点等发生变化时重新判断适用路径。

**验收标准。**

- 从跨境网络连接、海外云账号、远程运维和第三方服务反查出境清单，有没有未登记的数据流？
- 随机抽一条出境链路，能否说清适用哪条路径、为什么适用、相关材料是否仍在有效期？
- 境外接收方实际处理目的、数据范围和保存地点是否与评估和合同一致？
- 业务变化后是否重新判断出境路径，而不是沿用多年前的备案或评估结论？

### 建立个人信息安全治理、影响评估和事件机制

**法规要求｜第51—57条。** 个人信息处理者应制定内部制度、分类管理、权限控制、采取安全技术措施、开展培训和应急预案；符合法定情形时开展个人信息保护影响评估并留存记录。发生或者可能发生泄露、篡改、丢失时，应立即采取补救措施并依法通知有关部门和个人。

**落实与验收。**

- 明确个人信息保护责任人、组织职责、权限审批、分类分级、加密、去标识化、日志审计、培训和应急机制。
- 将个人信息保护影响评估嵌入敏感信息、自动化决策、委托/对外提供、公开、出境及其他高风险处理活动的立项和变更流程。
- 对个人信息安全事件建立发现、研判、补救、通知、复盘和整改闭环，并与网络安全/数据安全事件流程联动。
- 处理规模达到法定条件时，落实个人信息保护负责人等额外组织义务。

**验收标准。**

- 随机抽一个高风险项目，影响评估是在上线前真实参与决策，还是上线后补材料？
- 从账号权限反查岗位职责，离职、转岗、高权限账号是否及时收回并留下记录？
- 给出“凭证泄露但暂未确认是否下载个人信息”的场景，团队是否立即进入事件研判和补救流程？
- 最近一次个人信息安全事件中，补救措施、主管部门通知、个人通知判断和复盘整改能否形成一条完整证据链？
