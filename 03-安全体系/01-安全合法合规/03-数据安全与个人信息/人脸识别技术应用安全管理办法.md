# 人脸识别技术应用安全管理办法

人脸项目上线前，应能说明为什么需要人脸、拒绝刷脸后如何办理，以及原图和模板最终保存在哪里。以下依据[国家网信办、公安部令第19号正式文本](https://www.cac.gov.cn/2025-03/21/c_1744174262156096.htm)，法规要求与实施示例分别列明。

## 法规概览

| 项目 | 内容 |
| --- | --- |
| 公布与施行 | 2025年3月13日公布，2025年6月1日施行 |
| 适用范围 | 境内应用人脸识别技术处理人脸信息的活动 |
| 研发边界 | 第2条排除为技术研发、算法训练开展的相应活动；仍须判断个保法等其他义务 |
| 备案门槛 | 人脸信息存储数量达到10万人，30个工作日内备案 |
| 评估留存 | 事前开展个人信息保护影响评估；报告和处理记录至少保存3年 |

## 安全要求与实施

### 必要性、替代方式与同意分别判断

**法规要求｜第4—7、10、12条。** 处理应具有特定目的和充分必要性。存在能够实现相同目的或同等业务要求的非人脸方式时，不得将刷脸作为唯一验证方式；拒绝刷脸的用户应有合理、便捷的替代方式。国家另有规定的，从其规定。基于同意处理时取得单独同意并提供便捷撤回；不满十四周岁涉及监护人同意和专门规则。

**实施与验收。** 在需求评审中同时记录“必要性理由、替代方案、处理依据、撤回后的行为”。用测试账号分别完成刷脸、非刷脸和撤回同意三条路径。替代路径不得只是一个无人接听的客服电话；撤回后还应验证后台采集任务、模板调用和第三方接口是否停止相应处理。

### 设备内存储与最短保存是两项独立约束

**法规要求｜第8条。** 除法律、行政法规另有规定或者取得个人单独同意外，人脸信息存储于识别设备内，不通过互联网对外传输。保存期限不得超过实现目的所必需的最短时间，其例外是法律、行政法规另有规定。

**不能误读：**同意上传云端不等于同意无限期保存；模板仍可能属于人脸信息，不能因为不保存原始照片就排除保护义务。

| 检查对象 | 实施示例 | 通过条件 |
| --- | --- | --- |
| 采集与传输 | 抓取注册、识别、失败重试和调试流量 | 原图、模板、日志的真实流向与已批准方案一致 |
| 存储与副本 | 核对设备、对象存储、备份及供应商缓存 | 每个副本有目的、访问控制和期限 |
| 删除 | 终止服务或处理目的完成后执行删除 | 主库、缓存及受托方有可验证处置结果；依法保留项单独说明 |
| 特权访问 | 抽查管理员查询、导出和密钥权限 | 无未经授权的批量明文访问；操作可追到个人 |

表中的技术实现是建议，具体义务依据第8、14条及适用个人信息保护规则。

### 先评估，再上线；重大变化重新评估

**法规要求｜第9条。** 事前评估目的和方式的合法正当必要性、个人权益影响、泄露等风险及措施有效性。目的或方式变化、重大安全事件发生后重新评估。

评估不能只有“风险可控”。建议形成一张记录：`业务目的 → 替代方式 → 人脸数据流 → 风险 → 控制 → 实测证据 → 剩余问题`。例如将门禁从设备内比对改为云端统一比对，应重新核验上传依据、接收方、集中存储风险及评估结论，不能沿用原设备方案的审批。

### 达到门槛后办理备案、变更与注销

**法规要求｜第15条。** 达到10万人之日起30个工作日内向所在地省级以上网信部门备案；实质变更、终止应用分别在30个工作日内办理变更或注销。

备案材料包括处理者基本情况、处理目的和方式、存储数量及安全措施、处理规则和操作规程、影响评估报告。统计以实际存储涉及的人数为基础，不用照片张数、识别请求数或注册总人数直接替代。

**验收示例。** 保存达到阈值的原始统计、计算口径、备案材料版本及提交回执。达到十万人当天即进入办理窗口；不能等年度盘点才发现已超过门槛。注销备案后，继续验证数据处理和删除结果。

## 公共场所与产品边界

第13条要求公共场所安装设备具有维护公共安全的必要性、合理限定采集区域并显著提示；宾馆客房、公共浴室、更衣室、卫生间等私密空间内部不得安装。普通门禁、支付验证、公共场所辨识应分别分析，不能共享一份笼统的“刷脸同意书”。

企业可将上线证据整理为：必要性和替代方案、处理依据和用户交互、影响评估、数据流和配置测试、适用备案记录。本文不替代具体场景的法律适用判断。
