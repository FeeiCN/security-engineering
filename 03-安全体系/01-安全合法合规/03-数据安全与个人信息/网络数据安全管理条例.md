# 网络数据安全管理条例

本文用于把《网络数据安全管理条例》转成数据处理者可直接组织实施和检查的控制要求。

[法规概览](#overview) · [安全要求与实施](#requirements) · [法规原文](#reference)

## 法规概览 {#overview}

| 项目 | 内容 |
| --- | --- |
| 法规 | 《网络数据安全管理条例》，国务院令第790号 |
| 生效日期 | 2025年1月1日 |
| 主要适用对象 | 在境内开展网络数据处理活动的网络数据处理者，以及条例规定的部分境外处理活动 |
| 核心问题 | 网络数据安全基础控制、个人信息、重要数据、数据提供与委托、跨境、大型网络平台等 |
| 官方来源 | [中国网信网正式文本](https://www.cac.gov.cn/2024-09/30/c_1729384452307680.htm) |

下文按 **“法规要求 → 落实与验收”** 展开：每项要求同时说明实施动作与可验证证据。实际工作中还需与网络安全法、数据安全法、个人信息保护法及行业规则叠加适用；实施建议不能替代条款的具体适用条件。

## 安全要求与实施 {#requirements}

| 核心主题 | 达成状态 |
| --- | --- |
| 基础数据安全 | 数据处理有制度、有技术控制、有事件能力 |
| 个人信息 | 收集使用最小必要，权利与高风险场景受控 |
| 重要数据 | 识别、申报、负责人、机构和年度评估真实运行 |
| 提供、委托与共同处理 | 数据流向清楚，接收方和合同风险受控 |
| 数据跨境 | 出境路径判断正确，材料与真实数据流一致 |
| 平台与供应链 | 第三方产品、平台生态和供应链风险持续管理 |

### 建立网络数据安全基础控制

**法规要求｜第9—13条等。** 在网络安全等级保护基础上采取必要安全措施，建立制度并处置事件。第10条规定产品、服务缺陷和漏洞涉及危害国家安全、公共利益时，还应在24小时内向有关主管部门报告；这不是所有缺陷统一适用的报告条件。

**落实与验收。**

- 建立网络数据资产、处理活动和责任清单，关联业务、系统、数据类型、责任人和主要控制。
- 将访问控制、加密、备份、认证、日志、漏洞修复、事件处置等纳入统一安全基线。
- 对网络产品和服务的漏洞、安全缺陷建立接收、评估、补救、用户告知和主管部门报告流程。
- 对委托处理、共同处理、对外提供等数据流转场景设置适用的评估、合同和退出要求。

**验收证据。**

- 从生产数据库和接口反查数据资产清单，是否存在未纳管数据？
- 随机抽一个关键数据系统，权限、备份、加密、认证和日志是否真实启用？
- 最近一次产品漏洞或数据风险是如何发现、修复和验证关闭的？
- 发生安全事件时，谁负责止损、判定影响、通知和报告，能否从真实记录还原？

### 规范个人信息处理和个人权利保障

**法规要求｜第三章。** 条例细化告知、最小必要、自动化采集、个人权利和个人信息转移等要求。第28条对处理1000万人以上个人信息的处理者，进一步适用第30、32条的相应要求；不能将其扩大为自动适用重要数据处理者的全部条款，也不能直接推定这些个人信息全部成为重要数据。

**落实与验收。**

- 将个人信息处理活动、合法基础、告知、同意、保存期限和个人权利机制与真实系统保持一致。
- 自动化采集技术不得突破最小必要和合法处理边界，对用户行权不得设置不合理条件。
- 达到1000万人以上时，逐项核对第30条负责人、管理机构及职责，以及第32条重大组织变化等相应要求。
- 个人信息处理活动变化时同步更新规则、评估和技术控制。

**验收证据。**

- 对照SDK、埋点、接口和数据库字段检查告知与真实处理是否一致？
- 现场发起查阅、复制、更正、删除等请求，能否跨系统实际完成？
- 自动采集逻辑是否存在默认全收、事后筛选的情况？
- 处理规模达到1000万人以上时，第30、32条对应责任与流程由谁落实，有什么证据？

### 识别并重点保护重要数据

**法规要求｜第29—33条。** 按规定识别、申报重要数据；重要数据处理者明确负责人和管理机构，每年度评估并按规定报送。相关程序还需衔接[网络数据安全风险评估办法](./网络数据安全风险评估办法.md)。

**落实与验收。**

- 建立重要数据候选识别、申报、确认和动态维护流程，不能把尚未收到目录通知等同于无需识别。
- 明确网络数据安全负责人和管理机构，赋予实际治理职责和参与重大数据活动决策的权限。
- 对重要数据的目的、种类、数量、方式、范围、保存期限、地点、对外提供、委托、共同处理和出境情况建立台账。
- 每年度开展风险评估并按适用要求报送，发现风险形成整改闭环。

**验收证据。**

- 从高价值业务数据反查重要数据候选清单：为什么纳入或排除，依据是什么？
- 随机抽一个重要数据集，负责人能否现场说明处理范围、系统、接收方和最近风险？
- 最近一次年度评估是否验证了真实权限、数据流和技术控制？
- 并购、分立、解散、破产等重大变化时，是否存在重要数据处置和报告机制？

### 管住数据提供、委托和共同处理

**法规要求｜第12、31条。** 提供、委托处理个人信息和重要数据时，约定处理及保护义务并监督接收方，相关处理情况记录至少保存3年；共同处理应约定各自权利义务。重要数据提供、委托及共同处理前应风险评估，属于履行法定职责或法定义务的例外应分别核验。

**落实与验收。**

- 建立数据接收方和处理场景清单，记录目的、范围、数据种类、保存期限、责任和退出方式。
- 合同约束接收方的数据安全义务，并在合作期间持续监督。
- 对重要数据的相关活动核对评估条件，评估接收方、合同约束和技术管理措施；不评估时保留适用例外依据。
- 合作结束后验证权限关闭、接口停用和数据删除或返还。

**验收证据。**

- 从API流量、文件交换、SDK和采购合同反查接收方清单，是否存在清单外的数据流？
- 随机抽一个受托方，实际处理的数据是否超出合同和审批范围？
- 重要数据提供前的风险评估是否改变过方案或提出过实质整改？
- 合作终止后，能否证明对方已经无法继续访问并按约定处置数据？

### 正确判断和管理数据出境

**法规要求｜第五章。** 条例规定网络数据出境条件，并与安全评估、个人信息保护认证、标准合同及相关豁免衔接。

**落实与验收。**

- 从真实网络连接、海外云、远程访问、集团共享和第三方服务建立数据出境地图。
- 对个人信息、重要数据分别判断适用路径；未被告知或公开发布为重要数据的场景按条例及配套规则处理。
- 出境前完成适用的告知、单独同意、影响评估及相应出境程序。
- 出境范围、目的、接收方、保存地点等变化时重新判断，持续监督境外接收方履约。

**验收证据。**

- 从海外域名、云账号、跨境专线和运维账号反查出境清单，是否存在实际出境但未登记的数据流？
- 随机抽一条出境链路，适用路径和豁免依据能否被独立复核？
- 备案、认证或评估材料中的数据范围与实际出境字段是否一致？
- 最近一次业务变化是否触发过重新判断？

### 管理平台、第三方产品和供应链风险

**法规要求｜第六章。** 网络平台服务提供者承担相应平台数据安全义务；大型网络平台按具体条件承担额外要求。大型平台定义还需核对第62条，不能仅以公司自称“大平台”判断。

**落实与验收。**

- 明确平台方、平台内经营者、第三方产品或服务提供者的数据安全责任边界。
- 对第三方接入实施准入、权限、接口、审计、异常监测和退出管理。
- 按法定定义识别大型网络平台，逐项映射其适用的报告和风险管理义务。
- 平台规则、自动化决策和数据接口重大变化进入安全与隐私评审。

**验收证据。**

- 从平台开放接口和第三方应用清单反查，是否存在未审批的高权限接入？
- 平台规则规定的安全责任能否在合同、接口权限和实际处置中得到验证？
- 适用大型网络平台要求时，额外义务由谁负责、最近一次履行记录在哪里？
- 第三方下线后，令牌、接口权限和历史数据是否真正被清理？
