# 中华人民共和国数据安全法

本文用于把《数据安全法》的原则性义务转成企业可以落地和验证的数据安全工作。

[法规概览](#overview) · [安全要求与实施](#requirements) · [法规原文](#reference)

## 法规概览 {#overview}

| 项目 | 内容 |
| --- | --- |
| 法规 | 《中华人民共和国数据安全法》 |
| 生效日期 | 2021年9月1日 |
| 主要适用对象 | 在境内开展数据处理活动的组织和个人；部分境外活动造成法定损害时也可能承担责任 |
| 核心问题 | 数据分类分级、重要数据保护、全流程安全管理、风险监测与事件处置、风险评估、数据交易与对外提供等 |
| 官方来源 | [工业和信息化主管部门收录文本](https://sdca.miit.gov.cn/zwgk/fgbz/art/2026/art_ce88eeb3d3744672a54923061c125885.html) |

下文按 **“法规要求 → 落实与验收”** 展开：每项要求同时说明实施动作与可验证证据。通用法律义务需要结合《网络数据安全管理条例》、行业重要数据目录及专项监管规则一起落地。

## 安全要求与实施 {#requirements}

| 核心主题 | 达成状态 |
| --- | --- |
| 数据资产与分类分级 | 知道有什么数据、重要程度和保护等级 |
| 全流程安全管理 | 收集、存储、使用、加工、传输、提供等活动都有控制 |
| 重要数据保护 | 重要数据范围、责任人、风险和报告机制清楚 |
| 风险监测与事件处置 | 数据风险能被发现、研判、处置和报告 |
| 风险评估与审查 | 高风险活动有事前判断和持续评估 |
| 对外提供与跨境 | 数据给谁、为何提供、能否提供均可解释和追溯 |

### 建立数据分类分级和重要数据识别机制

**法规要求｜第21条。** 国家建立数据分类分级保护制度，并对重要数据实行重点保护；各地区、各部门确定重要数据具体目录。

**落实与验收。**

- 建立统一数据资产目录，能够关联业务、系统、数据负责人、数据类型和处理活动。
- 建立企业数据分类分级规则，并与国家、行业重要数据目录和专项监管规则衔接。
- 对可能属于重要数据的场景建立识别、申报、确认和变更机制，不能只靠字段敏感性标签替代重要数据判断。
- 数据、系统和业务发生重大变化时重新评估分类分级结果。

**验收证据。**

- 从数据库、对象存储、消息和数据平台反查目录，是否存在长期运行但未进入资产清单的数据？
- 随机抽一个高价值数据集：为什么是这个级别，依据是什么，负责人是谁？
- 对照行业重要数据目录和业务变化记录，是否存在“未被主动识别，因此默认不是重要数据”的情况？
- 分类分级调整后，权限、加密、日志和审批控制是否同步变化？

### 落实数据处理全流程安全管理

**法规要求｜第27条。** 开展数据处理活动应建立健全全流程数据安全管理制度，组织开展教育培训，并采取相应技术措施和其他必要措施保障数据安全；利用网络开展数据处理活动还应在网络安全等级保护制度基础上履行相关义务。

**落实与验收。**

- 把数据安全控制嵌入收集、存储、使用、加工、传输、提供、公开和删除等环节。
- 明确数据安全责任人、岗位权限、审批、日志、加密、备份、脱敏、导出和销毁等控制。
- 将数据安全评审纳入系统上线、数据产品、数据共享、第三方接入和重大变更流程。
- 按岗位开展数据安全培训，对高权限和高风险岗位强化责任与操作要求。

**验收证据。**

- 随机选一条数据从产生到删除做穿行，哪个环节没有责任人、审批或日志？
- 抽查高权限账号和批量导出场景，是否可以绕过最小权限和审批直接获得数据？
- 数据离开生产系统进入分析、测试、备份或第三方环境后，保护强度是否明显下降？
- 从真实项目反查安全评审记录，是否存在“先上线、后补评审”的情况？

### 对重要数据实施更严格保护

**法规要求｜第27、30条。** 重要数据处理者应明确数据安全负责人和管理机构，落实保护责任；并按规定定期开展风险评估，向有关主管部门报送风险评估报告。

**落实与验收。**

- 对重要数据明确安全负责人、管理机构、处理目的、范围、系统、流向和保护措施。
- 重要数据的共享、委托、重大变更和跨境等高风险活动进入专项评估和审批。
- 按适用要求开展重要数据风险评估并形成报告，发现问题有责任人、期限和整改闭环。
- 将重要数据处理活动与行业主管部门要求、申报和报告机制衔接。

**验收证据。**

- 随机抽一个重要数据集，能否现场说清存在哪些系统、谁能访问、提供给谁、最近一次评估发现什么问题？
- 重要数据负责人是否真实参与重大处理活动决策，还是只存在任命文件？
- 最近一次风险评估是否使用真实数据流、权限和日志验证控制有效性，还是主要审制度？
- 评估发现的问题是否全部能追到整改和复测结果？

### 建立数据安全风险监测和事件处置机制

**法规要求｜第29条。** 数据处理活动中应加强风险监测，发现数据安全缺陷、漏洞等风险时立即采取补救措施；发生数据安全事件时立即处置并按规定告知用户、向有关主管部门报告。

**落实与验收。**

- 联通数据访问、导出、数据库审计、DLP、安全告警、业务异常和外部泄露线索等风险来源。
- 明确数据安全事件的研判、升级、止损、取证、报告和复盘责任。
- 对“可能泄露但尚未完全确认”的线索保留快速研判和止损能力，不能等待最终结论才启动处置。
- 将数据安全事件与网络安全、个人信息和行业专项事件报告机制统一编排，避免漏掉并行义务。

**验收证据。**

- 从真实异常导出、数据库高风险操作和泄露情报中反查事件台账，有多少线索从未进入数据安全研判？
- 给出“生产凭证泄露但暂不能确认数据是否被下载”的场景，团队第一小时实际会做什么？
- 最近一次数据安全事件中，发现、止损、影响评估、报告和整改的时间线能否完整还原？
- 安全事件与个人信息/行业监管报告是否由同一事实链触发，还是各团队各自判断导致漏报？

### 对高风险处理活动开展风险评估和安全判断

**法规要求｜第24、30、31条等。** 国家建立数据安全审查等制度；重要数据处理者承担定期风险评估义务，对可能影响国家安全的数据处理活动还可能适用国家安全审查等要求。

**落实与验收。**

- 为重要数据、高敏感数据、重大数据共享、并购迁移、关键数据平台和新技术处理等场景设置风险评估触发条件。
- 评估至少覆盖处理目的、数据范围、接收方、权限、技术措施、供应链和事件风险，并形成可执行整改任务。
- 对可能触发数据安全审查、网络安全审查或行业审批的事项建立前置判断，不以项目进度替代合规判断。

**验收证据。**

- 随机抽一个重大数据项目，风险评估是在决策前影响方案，还是项目上线后补文档？
- 评估结论写“风险可控”时，依据哪些事实、测试和数据？
- 对重大采购、并购、跨境和平台数据处理活动，谁负责判断是否触发其他审查机制？
- 风险评估里的整改项是否进入项目门禁和后续复测？

### 管理数据提供、交易和境外执法请求

**法规要求｜第33、36条等。** 从事数据交易中介服务应依法履行相关审核义务；境内组织、个人向外国司法或者执法机构提供境内存储的数据，应按规定履行主管机关批准程序。

**落实与验收。**

- 对外提供数据时记录接收方、目的、范围、合法依据、合同、安全措施、保存和退出要求。
- 对数据交易、数据中介和第三方撮合场景建立来源、交易双方身份等必要审核机制。
- 涉及境外司法或执法机构的数据请求时，建立法务、安全和主管机关审批路径，业务团队不得自行直接提供。
- 数据跨境同时按个人信息、重要数据和专项跨境规则另行判断。

**验收证据。**

- 从API、文件交换、数据产品和第三方合同反查对外提供清单，是否存在未登记数据流？
- 随机抽一个接收方，实际收到的数据是否超出合同和审批范围？
- 模拟收到境外执法机构要求提供境内数据的请求，团队是否知道必须进入专门审批而不是直接响应？
- 合作终止后，能否证明对方不再持续获取数据并按约定删除或返还？
