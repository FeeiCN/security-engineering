# GA/T 2182-2024 关键信息基础设施安全测评要求

本标准面向关基安全测评，与[GB/T 39204](./GB-T-39204-2022-关键信息基础设施安全保护要求.md)的保护要求配套理解。[公安部标准公开信息](https://ywtb.mps.gov.cn/gabzh/portal/stdDetail/309911)列明：2024年12月26日发布，2025年5月1日实施。

以下提供企业侧测评准备与复核方法。正式测评单元、关联评价和结论应按标准全文执行，本文不代设评分和通过线。

**原文获取状态。** [公安部标准信息页](https://ywtb.mps.gov.cn/gabzh/portal/stdDetail/309911)目前提示“该标准暂不提供文本阅读”。本站尚未取得可核验的正式全文，因此下文不能作为逐条标准解读；待取得正式版本后再补条款对应与原文转写，不采用标准计划或第三方转载代替。

## 测评定位

| 项目 | 内容 |
| --- | --- |
| 测评对象 | 已依法认定的关基及其关键业务、系统与依赖 |
| 输入基础 | 正式边界、GB/T 39204保护要求、已有等级测评及实际运行证据 |
| 企业侧重点 | 核对范围、证据有效性、跨系统关联风险及整改复测 |
| 结果边界 | 具体测评方法、判定和结论以GA/T 2182正式全文为准 |

测评准备应能回答三个问题：哪些关键业务被覆盖，已有证据支持哪些判断，哪些跨系统风险仍须验证。下文的检查项是企业侧准备方法，不是对标准条款或评分规则的转述。

## 测评输入先覆盖关键业务

输入包括正式认定范围、关键业务及依赖、相关等级保护对象和测评材料、架构变更、供应链、监测、应急与历史风险。一个关基涉及多个对象时，分别核对覆盖情况，不能只提供其中“核心系统”的等保报告。

| 范围问题 | 需要取得的事实 |
| --- | --- |
| 关基边界是什么 | 正式认定、业务范围及生产架构之间的对应关系 |
| 哪些依赖影响业务 | 身份、密码、网络、云、数据库、外部服务和运维权限 |
| 哪些材料可复用 | 等级测评对象、标准版本、时间、样本和实际变更 |
| 哪些部分需专项验证 | 未被已有证据覆盖的强化控制及跨系统关联风险 |

测评边界由事实与适用依据决定，不能直接以合同列出的采购设备为边界。

**核验。** 从正式认定清单抽取一个关基，能否找到对应业务链、生产架构、关联等保对象与当前测评范围？从实际第三方接入或共享服务反查，是否有影响业务却未进入范围的依赖？

## 复用已有证据的四项检查

**对象一致。** 证据覆盖的系统、地域和版本是否与当前关基相符。

**时间有效。** 证据形成后是否发生架构、权限、供应商或业务重大变化。

**方法足够。** 已有证据能够支持本次具体判断，不能用访谈摘要证明实际阻断效果。

**限制明确。** 未抽样、未能验证和不适用事项分别记录；缺少证据不能被写成已符合。

这些是企业证据复核方法。测评组织应按照本标准关于与等级测评衔接的正式要求安排工作，不能因为有一份等保报告就宣称关基测评已完成。

**核验。** 随机选一项准备复用的控制证据，能否指出其覆盖对象、形成时间、取证方法和不适用范围？对已变更系统，是否保留变更后的重新验证，而非仅沿用历史报告结论？

## 专项与关联风险如何验证

| 关注点 | 实施性测试示例 | 预期证据 |
| --- | --- | --- |
| 业务依赖 | 受控模拟共享认证或关键外部服务不可用 | 影响判断、告警、降级和恢复结果 |
| 供应链控制 | 核对厂商远程运维、更新和退出通道 | 真实账号、权限、操作及终止后的回收 |
| 监测联动 | 在授权范围回放可识别的测试事件 | 从发现、研判到处置的完整时间线 |
| 组织责任 | 穿行一次重大风险和上线决策 | 责任人、授权、决策及后续整改 |
| 恢复能力 | 验证关键业务链而不只启动备用主机 | 数据一致性、依赖恢复和实际目标达成情况 |

测试要明确授权、范围、业务保护和停止条件，不将生产破坏性测试当作所有项目的默认动作。

### 把单项发现放回业务链

**实施。** 为每项发现记录对应资产、控制、原始证据和影响的业务环节。共享身份、网络、云平台或供应商问题涉及多个测评对象时，另记录共同原因和关联影响，供正式测评人员按适用方法评价。

**核验。** 从一个跨系统问题反查，是否能识别所有受影响对象？从一条业务中断路径正查，是否能看到各对象间的依赖及已有控制的实际作用？不能把各系统单项结果简单相加，当作关基整体风险结论。

### 让测试结果可复现、可复核

**实施。** 对访谈、配置核验、日志分析和受控测试分别记录时间、环境、对象、样本、操作、观察结果与限制条件。涉及生产业务时，测试方案应先明确授权、回退和停止条件。

**核验。** 换一名复核人员，能否根据记录找到相同对象并理解结论从何而来？无法复现或未测试的事项应标明限制，不能以“未发现问题”代替“已验证符合”。

## 从发现项到可关闭的问题

**示例。** 关基涉及三个等级保护对象，供应商用同一长期账号管理全部对象。各系统日志都有记录，但无法区分具体人员，且供应商退出后账号仍可使用。

发现项应记录账号、访问范围、实际状态、依据及业务影响。整改同时处理实名授权、到期、日志关联和退出验证；复测从原访问通道发起，不能仅检查新写的制度。

如果跨系统同源问题被拆成三个低影响问题分别关闭，整体风险仍可能存在。企业应保存单项事实、关联影响和统一整改之间的对应关系，正式风险与测评判定由适用依据确定。

**核验。** 整改后重新从供应商实际访问入口测试，确认旧账号、共享凭证及跨对象权限已失效；同时抽查审计记录能否定位到具体人员。只查看新制度或销户工单不足以关闭原发现。

## 验收输出与官方入口

企业侧交付材料宜能串联：范围、已有材料复用说明、专项验证、发现及依据、业务影响、整改复测和剩余限制。正式报告内容与结论须依标准全文和实际测评程序确定。法规规定的检测评估、事件报告等义务仍按各自条件执行，不能由一次测评结果概括替代。
